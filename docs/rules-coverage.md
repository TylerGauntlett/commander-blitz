# Rules coverage

This is the honest artifact. It says what the engine does, where it takes a shortcut,
and what it refuses to model at all. If you want to know whether this engine can
handle your card, read this page.

The short version: **everything the two shipped decks need is implemented and tested.**
The simplifications below were chosen so that removing them later is additive work,
not a rewrite.

## Implemented

| Area | Detail |
|---|---|
| **Turn structure** | All 13 steps, turn-based actions, correct priority windows, cleanup repeating per rule 514.3a, and **additional phases** — see below |
| **Additional combat and main phases** | "After this main phase, there is an additional combat phase followed by an additional main phase" (506.1, 505.1b). `Step` is an ordered `IntEnum` walked one integer at a time, so a repeated phase had no representation — and needs none, since an extra phase is the same steps entered again. What has to be remembered is only that the phase the turn was *about to* enter is still owed: `GameState.extra_phases` queues the phase kinds a card granted and `resume_step` is the one bookmark the turn comes back to. So an extra combat granted in a precombat main is *inserted* in front of the combat the turn already had rather than eating it, and Combat Celebrant's extra combat returns to the bookmark rather than falling through into a postcombat main it never granted. The queue is read only when a main or combat phase ends, which is what makes "after this main phase" right for an Aggravated Assault activated in an upkeep; an unspent grant expires at the turn boundary. The additional main phase is a `POSTCOMBAT_MAIN` step (505.1b) and fires the per-phase `postcombat_main` trigger, and it is not an extra land drop, because `lands_played` is reset by the untap step |
| **Priority** | APNAP order, retaining priority after acting, auto-pass when passing is the only option |
| **The stack** | LIFO resolution, responses, countering, fizzling when every target became illegal |
| **Casting** | Timing restrictions (sorcery speed vs instant vs flash), targets chosen at cast time and re-checked on resolution |
| **Mana** | Cost parsing, mana pools emptying per step, automatic payment with a backtracking solver, `X` costs |
| **Combat** | Attacker/blocker declaration, evasion, damage assignment order, simultaneous damage, first and double strike as separate sub-steps |
| **Keywords** | flying, reach, trample, deathtouch, lifelink, vigilance, haste, menace, first strike, double strike, defender, hexproof, shroud, indestructible, flash, the six landwalks (five basic types plus nonbasic), skulk, fear, intimidate, horsemanship, shadow, wither, infect, totem armor. `partner` is accepted but inert — see below. Every Magic keyword, routed to a mechanism and marked shipped / free / routed / blocked, is censused in [keywords.md](keywords.md) |
| **Triggers** | ETB, dies, leaves-the-battlefield, landfall, land-played, spell-cast, attacks, blocks, combat damage to a player, upkeep, draw step, begin combat, end step, life gain, counters placed, draws, discards (every one of them: a discard effect, the cleanup trim to hand size, and a cycling cost), damage dealt to a permanent (enrage — the event was always fired and nothing subscribed to it; the subscription is scoped to the *victim*, because for this one event the subject and the source are two different creatures), becoming the target of a spell or ability (heroic and ward, fired as it goes on the stack per 603.2d, with the `controller` clause asking whose spell it is rather than whose permanent), becoming blocked or going unblocked (flanking, rampage, bushido, frenzy — a pair told from the attacker's side, both decided when the block declaration closes), and becoming untapped (inspired — the untap step now fires one event per permanent rather than one aggregate with a count). Intervening-if clauses re-checked on resolution. Delayed triggers ("at the beginning of the next end step, …") via the `delay` op |
| **Command zone** | Abilities that work from the command zone (Edgar Markov's eminence), commander tax, commander damage, the zone-change replacement |
| **Static abilities** | Anthems, keyword grants, P/T setting (including `*/*` read off the board), subtype grants, type replacement, "as long as" conditions (a boolean tree over counters, board and zone counts, and whose turn it is — Threshold), "can't block" (unleash — the mirror of `cant_attack`, checked in `can_block` because it is a fact about one creature rather than about the whole declaration, and a static rather than a keyword because it is a permission), and the player-wide ones: extra land drops, no hand limit, playing lands from the graveyard or the top of the library, doubling land triggers, doubling land *mana*, and freezing the lands an opponent taps |
| **State-based actions** | All nine listed in [engine-rules.md](engine-rules.md), plus **ten poison counters** (704.5c) |
| **Level up** | "Level up {2}… LEVEL 1-3 3/4… LEVEL 4+ 6/6, flying". Filed as a characteristic-defining subsystem and answered by the second half of its own census line: a band **replaces** the printed P/T rather than adding to it, which is `set_pt` and not `buff`, and a band is an interval, which a static's condition already says with `all` over two `counters` comparisons. What is left is a level counter (an ordinary counter) and an ability that adds one (an ordinary ability). The pipeline already runs `set_pt` and `grant_keyword` after reading a static's condition, and a counter is a pipeline input, so nothing here is characteristic-*defining* in the sense that would need a subsystem — and `+1/+1` counters still layer on top of the band, which is the correct order |
| **Epic** | "For the rest of the game, you can't cast spells. At the beginning of each of your upkeeps, copy this spell except for its epic ability" (702.50a). Both halves are about where the state lives: the card is in a graveyard a moment after it resolves, so neither can sit on it. The restriction is one-way player state (`has_city_s_blessing`'s shape) enforced in `_cast_actions`, which is also why lands are unaffected; the copy is a rule rather than an ability, for suspend's ticking reason, and goes through the same `put_copy_on_stack` `copy_spell` uses. "Except for its epic ability" is one condition — `not obj.is_token` — and without it each upkeep's copy re-points `epic_source` at itself, then is removed by a state-based action, silently ending the copying after exactly one turn |
| **Aura swap** | "{cost}: Exchange this Aura with an Aura card in your hand" — one op, because a bounce beside a put-onto-the-battlefield loads and goes wrong twice invisibly. The incoming Aura is not *cast*, so it has no targeting clause to carry a creature and `_attach_aura` never runs; a state-based action then bins it, and the ability reads "exchange" while being a slow Naturalize on your own card. And the exchange would not be atomic — between the two moves the enchanted creature is unenchanted. The attach happens after the move, since `reset_permanent_state` clears `attached_to` on the way in. An empty hand does nothing rather than bouncing the Aura for free |
| **Soulbond** | "Pair this creature with another unpaired creature when either enters… As long as this creature is paired, **both** creatures get +1/+1." `attached_to` is the nearest existing relationship and is wrong twice over: it is one-way, so a one-sided link buffs exactly one of the two; and an Aura attached to nothing is binned by a state-based action, where a creature whose partner died is simply unpaired. Two lifetimes, two fields. `paired_with` is therefore symmetric, and breaking it is two writes — the leaving object's own is cleared by `reset_permanent_state`, the *partner's* in `_detach_all`, since nothing else walks back along the link and a creature pointing at a card in a graveyard would keep the bonus for ever. The static is written once and applies to two creatures, hence `paired` and `paired_with_source`; both are board state, so neither makes one static depend on another's output |
| **Ninjutsu** | "{1}{U}, Return an unblocked attacker you control to hand: Put this card onto the battlefield from your hand tapped and attacking." Two missing words, one per half. `blocked` is a new selector key and is *not* the negation of `blocking` — that asks whether a creature is blocking something, this asks whether anything is blocking **this attacker**, and they are different creatures. `attacking` is `create_token`'s clause moved onto `put_onto_battlefield`, joining the combat the returned attacker just left, which is why the ninja arrives unblocked. It was never *declared* as an attacker (508.4), so it triggers nothing that fires on attacking. The ability is offered from hand and satisfies the outside-the-battlefield guard through unearth's satisfier, which ninjutsu is the clearest case for: nothing in the *cost* removes the card, and it leaves hand because the effect puts it onto the battlefield |
| **Face-down permanents — morph, megamorph, manifest** | A face-down permanent is `chars` returning a **2/2 colourless creature with nothing else**, before any layer, while `card_of` goes on answering with the real card — which is what turning it face up needs to find it again. The census called it a subsystem and it is a small one, because `card_of` (built for `transform`) and `chars` were already single choke points. Morph *casts* a card face down for `{3}` (fixed by 702.37a) and turns up for its printed morph cost; manifest puts one there off the library and turns up for the hidden card's own cost, and only if it is a creature card (701.34c). Turning face up reuses `ActionKind.ACTIVATE` with `ability_index` 0 — free, because a face-down permanent has no abilities — so the RL action space is unchanged. Three suppressions in three places keep the hidden card from leaking: abilities not offered (`legality`), triggers not listening (`triggers`), characteristics not computed (`chars`). **Divergences**: anthems and counters do not apply, since the shell is returned rather than layered over; and turning up is an ordinary activation rather than a special action, observable only to something that could respond, and nothing can |
| **Banding** | "Any creatures with banding, and up to one without, can attack in a band. Bands are blocked as a group. If any creatures with banding you control are blocking or being blocked by a creature, you divide that creature's combat damage." (702.21) Previously **refused** on the grounds that it "needs player-chosen combat damage assignment, which the engine automates for every creature". Half right, and the wrong half is the interesting one: the engine does not *lack* damage assignment order — it has had `CombatState.block_order` all along and has simply been **sorting it instead of asking**. The automatic sort by effective toughness *is* a choice made silently on the attacking player's behalf, so banding is two sentences rather than a subsystem: ask, and ask the other player. `ask_objects` already records the order options were taken in, which is what a damage assignment order is, so no new `DecisionKind` was needed. 702.21b is asked as **two** questions because the printed sentence is two constraints — any number of attackers *with* banding, then at most one *without*, attacking the same player; a single question cannot say the second, and validating afterwards means offering a choice the engine then refuses. 702.21e is `CombatState.band_of`, which returns a band of one for everything else, so every combat without banding falls straight through and asks nothing. `_divide` is 510.1c walked once and pointed either way. **Divergence**: the *ordinary* case still sorts rather than asking — see manual damage division below. That is a statement about who is asked when no banding is involved, and it is unchanged by this |
| **Daybound / nightbound** | "If a player casts no spells during their own turn, it becomes night next turn" (726). Previously **refused** as needing "a game-wide designated state the engine has no place to keep" — an accurate description of the problem, whose answer is one field. `GameState.day_night` is the same shape `turn` and `step` already are, because day and night belong to the **table** rather than to a player or a permanent, and the state object is where the table's facts live. Everything else existed: `TurnLedger.spells_cast` (which storm folds in `emit`) answers "cast no spells during their own turn"; `transform` turns the permanents over; and `chars` answers which way round one is, because daybound is printed on the front face and nightbound on the back — so the switching code keeps no record of its own. Switched in a turn-based action beside phasing, at the start of the next turn, which is both where 726 asks and the last moment the previous turn's ledger still exists. **Two boundaries**, both of which a naive version gets wrong in the same direction: it starts as *neither* day nor night (a game with no daybound permanent never has a day, and "if it's day" must say no), and the first untap step of the game has no previous turn, whose empty ledger would otherwise read as "cast no spells" |
| **Phasing** | "This phases in or out before you untap during each of your untap steps" (702.26). Previously **refused** as changing how the untap step works for every permanent in the game; it changes it for one permanent, once. 702.26c — "a phased-out permanent is treated as though it does not exist" — is a **list membership**: the permanent leaves `state.battlefield` and stays in `state.objects`, the same nowhere a card on the stack and a card under a merged permanent already occupy. Targeting, the state-based actions, the characteristics statics, the combat declarations and the serializer all walk the battlefield, so every one of them misses it with no test of its own. Three rules then hold because nothing moved: no zone change (so no leave/enter triggers), counters and auras and damage survive (`reset_permanent_state` never runs), and 702.26f's "continuously on the battlefield" is free because `entered_turn` is untouched. 702.26e is the one part written explicitly: what is attached phases out *with* its host and comes back with it, marked `phased_out_indirectly` — without it the Aura would be left alone and binned by a state-based action, and the permanent would phase back in naked. 702.26b is a toggle, so both lists are read before anything moves |
| **Meld** | "At the beginning of your end step, if you both own and control X and Y, exile them, then meld them into Z" (701.37). Previously **refused** for the same words flip was — "a card-wide designated state the engine has no place to keep" — and by the time mutate shipped, the place existed. It is the merged permanent again: one `CardDef` read through `card_of`, the partner in `merged_under` so `move_object` sends the pair together. Two things change from mutate and both are simplifications — the pair is fixed by `melds_with` rather than targeted, and the result is a **third** card entry (`melds_into`) rather than a computed union. The one genuinely harder part is that meld makes a *new* permanent: 701.37c exiles both cards and returns them melded, so it enters the battlefield with its enter triggers firing and summoning sickness applying — which is why the op exiles and re-enters, and why `merged_card` is set after the move (`reset_permanent_state` clears it on the way in). The melded entry is kept out of decks by `parent_face`, the same back-link a back face and a second castable face use. "If you both own and control" is the card's own intervening-if, checked twice by `triggers` per 603.4 and deliberately **not** re-checked in the op |
| **Flip cards** | "At the beginning of the end step, if you control three or more Elks, flip this" (711). Previously **refused** as needing "a card-wide designated state the engine has no place to keep", and it needs none: it is `back_face` plus the `transform` op, both shipped for Bloodline Keeper. Every difference between a flip card and a transforming double-faced one is about the cardboard — one turns over, the other turns 180° — and the engine says both the same way, with `card_of` returning the other `CardDef`. 711.4 ("it is the same permanent": counters, auras, damage and tapped status survive) holds because nothing moves, and a flipped permanent that leaves the battlefield comes back unflipped by 712.13a, which `reset_permanent_state` already applies. Reclassified from `refused` to **free** with `tests/unit/test_flip.py` as the witness — the point of the witness being that a status nobody checked is a status nobody should trust |
| **Mutate** | "Mutate {1}{G} — if you cast this spell for its mutate cost, put it over or under target non-Human creature you own. They mutate into the creature on top plus all abilities from under it" (702.140). The census called this the one genuine subsystem it had left, and the argument — "a `GameObject` is one card, and every choke point assumes that" — has a true premise and a backwards conclusion. **Because** `card_of` is a single choke point, a merged permanent is one `CardDef` synthesised at merge time: the top card, carrying the abilities of everything under it. `chars`, legality, triggers, `stack.ability_of` and the serializer all read it through `card_of`, in one ability index space, and not one of them changed. The subsystem feared was the alternative implementation. It composes, too — mutating onto an already-merged pile reads the previous union and adds to it. The pile is the new part: the cards underneath sit in `state.objects` and in **no zone list**, which is where a card on the stack already lives, and `move_object` sends them all wherever the permanent goes (read before `reset_permanent_state` clears the list — the snapshot persist already needed). Nothing else about the permanent moves, so counters, damage, auras and summoning sickness stay by construction (702.140c). "Over or under" is asked at **resolution** per 702.140b; asked at cast time it would be a choice made before anyone could respond. **Divergences**: the target excludes tokens, because a merged permanent is a pile of *cards* and there would be nothing to come back when it breaks up |
| **Bestow** | "Bestow {5}{W} — if you cast this card for its bestow cost, it's an Aura spell with enchant creature. It becomes a creature again if it's not attached to a creature" (702.103). The seventh alternative cost and the first that is not only a price: every other one changes what a spell costs and leaves what it targets alone, and 702.103a supplies "enchant creature" from the rule, so `BESTOW_TARGET` carries it and no card writes one. The permanent half is `chars`, not `card_of` — while `attached_to` is set the object drops `Creature`, gains `Enchantment` and the `Aura` subtype and zeroes its P/T, and the moment it is not attached it is the printed creature again. Switching on `attached_to` is reading a pipeline **input** (the `attach` primitive writes it and no layer can change it), which is `is_attached`'s argument from reconfigure. Two things then follow with no code: the state-based action that bins an Aura enchanting nothing reads the *printed* card and so never sees a bestowed permanent — which is 702.103e agreeing rather than luck — and `_detach_all` already clears the link as the host leaves. **Not** a second castable face, though the census filed it as one: that is two spells, and this is one spell landing as two different permanents |
| **Fuse** | "You may cast one or both halves of this card from your hand" (702.102a). The one printed shape `card_of` cannot answer, because it is a single spell made of **two** faces at once — and the shape it needed already existed as **splice**. A spliced card's effects run after its host's through the same `EffectContext`, and that shared context is what makes them one spell rather than two; fuse is the same thing with the second effect list coming from the card's own other half. So nothing touches `card_of`: a fused cast builds one `CardDef` from the two — name joined, costs added, target lists concatenated — and hands it to the machinery that prices, targets and resolves any other spell. Built identically in `legality` and `Game._cast`, so the line priced and the spell cast cannot disagree. **Guards**: the two halves may not share a target id (they resolve in one context, so one would silently answer for the other); fuse needs a `second_face`; and that half must be castable from hand, since 702.102a casts from hand and an aftermath half may not be |
| **A second castable face — adventure, aftermath, split cards** | "Cast this card as its Adventure, then exile it; you may cast the creature later from exile" (715.3); "Aftermath — cast this spell only from your graveyard. Then exile it" (702.127a). The census grouped four keywords here and two of them were a different problem; these two are one mechanism. The engine already had **two `CardDef`s over one `GameObject`** — that is what `back_face` is — and what it lacked is a second face that is *cast*. So `showing_second_face` is set as the spell goes on the stack and cleared as it leaves, `card_of` answers with that face while it is set (asked before `transformed`, because being cast as a face is the narrower claim), and the cost, type line, targets, effects and logged name follow with nothing else changed. The two keywords differ in two words, which are the two extra fields: `second_face_zone` says where the half is offered from — aftermath's "only from your graveyard" is *where it is offered*, since there is no hand line to refuse — and `adventure` says whether the exile it lands in may be cast out of. The exile is the fifth rider on the resolving-spell destination, beside flashback, buyback, rebound and cipher, and the only one that reads the **printed** card rather than the face that resolved. Both faces' timings are asked separately off their own type lines (Brazen Borrower is a flash creature with an instant Adventure). **Divergences**: the rider fires only *as the spell resolves* (715.3c), so a countered or fizzled Adventure is an ordinary card in a graveyard — correct, and worth stating because the opposite is a free spell in exile. And the authoring pipeline still emits one card entry per answer file, so a two-faced card is two hand-written entries linked by id, exactly as `bloodline_keeper` / `lord_of_lineage` are |
| **Hideaway** | "When this permanent enters, look at the top four cards of your library, exile one face down, then put the rest on the bottom in a random order. {2}, Sacrifice this artifact: You may play the exiled card without paying its mana cost." The census listed it as waiting on *two* clusters — face-down exile and play-from-exile — and it needed neither whole. "Face down in exile" is `revealed_to`, which foretell shipped: a card nobody may interact with is hidden by not being shown, and the 2/2 shell is only needed on the **battlefield**, where somebody can point at it. What was genuinely missing is the permission — the engine could exile a card and could cast one for free, and had no way to say *"that one, from there"*. That is `play_exiled`, defaulting its selector to `{"zone": "exile", "controller": "any", "exiled_with": "self"}` and reading back the `exiled_by` link the exile wrote: the **permanent** is what later offers the card, so the permanent is what has to find it, which is imprint's direction rather than haunt's. The rest go to the bottom through `move_object` like every other zone change; editing the library list in place leaves cards whose `zone` still says `EXILE` sitting inside a library, and nothing but a test would notice |
| **Splice** | "As you cast an Arcane spell, you may reveal this card from your hand and pay its splice cost. If you do, add this card's effects to that spell." The only keyword that changes what a *different* card does: every other cost belongs to the card printing it, so this is offered in `Game._cast` between the host's own costs and `push_spell`. The card is **revealed, not spent** -- it stays in hand and can be spliced again, and discarding it would delete the mechanic's economy. The effects run through the host's own `EffectContext` after its own, so countering the host stops all of it. **Divergence**: a spliced card may not declare its own targets and the loader refuses one, since a target id written there would be missing in the host's context or collide with one of the host's |
| **Cipher** | "Exile this spell card encoded on a creature you control. Whenever that creature deals combat damage to a player, its controller may cast a copy of this card without paying its mana cost." The third direction an exile link can point: `exiled_by` names the exiler, `haunting` names a creature whose *death* matters, `encoded_on` a creature whose *combat damage* does. `encode` does **not** move the card — a resolving sorcery is placed after its effects run, so an exile written inside `spell_effects` is silently overwritten by the graveyard and the link wiped on the way — so encoding is the fourth rider on the destination, beside flashback's exile, buyback's hand and rebound's. `cast_copy` is not `copy_spell`: that copies something on the *stack*, and an encoded card is in exile with nothing there to point at. A copy does not encode again (702.97b), which is epic's `not is_token` guard for epic's reason |
| **Haunt** | "Exile it haunting target creature. When the creature this card haunts dies, …" The engine already had an exile link — `exiled_by`, naming the permanent that exiled the card — and that is the O-Ring direction, right there because the *exiler* is what goes away. Haunt is the mirror: the card in exile is what survives and has to notice a creature dying elsewhere, so the link points at the **victim**. `haunted_by` is a trigger filter answered off the **ability's source**, because the haunted creature has died and carries no record of who was haunting it; the ability lives in exile (`active_zones: ["exile"]`), the same widening the cycle trigger needed for the graveyard |
| **Cascade and ripple** | "Exile cards from the top of your library until…" and "reveal the top four…". The free cast already existed as `suspend.cast_for_free`; the **scan** did not — every other route to a library takes the top N or searches all of it, and cascade walks down to a depth the card cannot know. "Put the rest on the bottom in a random order" is shared and is deliberately **not** a shuffle, which would reorder the whole library and destroy a stacked top; it goes through `move_object` rather than editing the list, since half those cards are in exile and half never left. **Haste is not shared** — it belongs to suspend, and a cascaded creature that could attack at once would be a strictly better card, so `cast_for_free` grew an opt-in. Ripple is not cascade with a parameter: "the same name as this spell" compares against the *source*, which no selector key names |
| **Foretell** | "During your turn, you may pay {2} and exile this card from your hand face down. Cast it on a later turn for its foretell cost" (702.143a). The census called suspend "the nearest shape"; it is the *same* shape, and foretell shares its `ActionKind` — both exile a card from hand to be cast later, neither uses the stack, and neither can be countered. "Face down" is `revealed_to`, the private-information channel: a card in exile nobody may interact with is hidden by not being shown, which is a far smaller claim than a face-down **permanent** (a 2/2 shell over a real card, and a characteristics problem — the reason morph is still out). "On a later turn" is the whole price, so `foretold_turn` is recorded and compared: foretold and cast on the same turn is the printed cost in two instalments with the discount thrown in |
| **Replacements that stop to ask — dredge, madness, miracle** | Every replacement in the `replacements` whitelist is applied *synchronously and asks nothing*, which is why it is a whitelist on the card applied inline by `zones._enter_battlefield`. These three could never be entries in it: each puts a question to a player at the moment of the replacement. What they were actually waiting on is that **drawing and discarding had to become suspendable**, and that turned out small because `turn.begin_step` already ran through `Game._run` — the turn structure could carry a decision all along, and only `_draw_step` beneath it could not. `primitives.draw_cards` and `discard_cards` still ask nothing (that module's contract is intact); `engine/replacements.py` wraps them, and every draw and discard goes through it except the **opening hand**, which rule 103 deals before the game begins with no graveyard to dredge from and no turn to be first in. Three details are the keywords rather than plumbing: dredge **replaces** the draw, so dredging into an empty library does not deck you; madness exiles **either way**, so a declined card is in exile and not the graveyard; and miracle reads the draw tally *before* the draw bumps it. The cast in madness and miracle is a real cast at a real price — it uses the stack and can be countered — which is what separates it from `suspend.cast_for_free`, and an unaffordable one is not offered (118.4) |
| **Absorb** | "If a source would deal damage to this creature, prevent N of that damage" (702.63a) — the `prevent_damage` static. Protection is the near miss and is a *bigger* card in four ways, only one about damage: it prevents all of it and also stops the creature being blocked, enchanted and targeted, so an absorb creature written as protection is unblockable and untargetable. Parameterised on N, so a static rather than a keyword. The clause that decides everything is "**a source**" — prevention is per source and per instance rather than a pool that drains, which is why absorb 1 is printable at all: blocked by three 1/1s it takes nothing from any of them. Prevented damage was never dealt, so it is subtracted before the rest of the pipeline: no deathtouch mark, no lifelink, no ledger entry, and `DAMAGE_DEALT` carries the reduced number — while the excess is ordinary damage and still carries deathtouch |
| **Join forces** | "Starting with you, each player may pay any amount of mana." The one cost the whole table pays: every other cost in the engine hangs off one player, and `may`'s `pay` -- which grew a `player` spec for Rhystic Study -- asks that player once. Asked one unit at a time, which is forced rather than stylistic, since "any amount" has no ceiling to offer as a `choose_x` and a seat that stops paying is a seat that answered no. **Order is the card**: starting with the controller in turn order, so later players see what earlier ones put in, which is the whole politics of it at a pod. The total lands in a binding named by `as`, read back the way clash's `clash_won` is |
| **Forecast** | "Forecast — [cost], Reveal this card from your hand: … (Activate only during your upkeep and only once each turn.)" The first ability offered from hand whose cost does **not** remove the card, so the outside-the-battlefield guard gained a fourth satisfier: `activate_steps` **and** `once_each_turn` together. Both halves are required — `once_each_turn` alone is still a free ability every turn for the whole game, which is what the upkeep window prices. The step restriction is checked where `sorcery_speed_only` is, since both are permission to activate at all (602.5c), and "your" is the ordinary `is_your_turn` condition beside it. The cap counts **activations**, in a new `TurnLedger` tally: `resolutions_this_turn` already existed and is the wrong number, because an ability whose first activation was countered has still had its go |
| **Disturb** | "You may cast this card **transformed** from your graveyard for its disturb cost." Both halves shipped years apart and had never met — `graveyard_cost` is the cast and `transformed` is the face — and all the substance is *when* the face is turned. | **Fateseal** | "Look at the top card of target player's library. You may put that card on the bottom" — `scry` grew a `chooser` beside its `player`. Whose library and who decides are the same person for scry and different people for fateseal, which is the whole keyword: written without it the opponent would choose what to leave on top of their own deck, which is not a weaker fateseal but the opposite of one |
| **Proliferate** | "Another counter of each kind already there" (701.27a) — an op rather than an `add_counters` with a filter, because the kinds are read **per permanent at resolution** and differ between them: one proliferate grows a +1/+1 here and a charge counter there. It never starts a kind, and a kind pruned to zero is not a kind. Simplified in the documented way: it proliferates every permanent you control that has a counter rather than offering a free multi-select, since the choice only matters for counters you would rather not grow. `objects` narrows it |
| **One-way words** | "…and it becomes renowned" — the `set_flag` op and the `has_flag` condition, over a `flags` set on the object. Renown's whole content is that it happens once, and the counters cannot stand in for the flag: gating on "has no +1/+1 counters" would renown a creature again as soon as anything removed them. A set rather than a boolean per adjective, because each new printed word would otherwise be a field, a condition leaf and an op. `monstrous` keeps its own field — it carries an event and an op that read it. The flag clears with the rest of the battlefield state, so a creature that leaves and returns may be renowned again (400.7) |
| **Moving counters** | Graft and modular — the `move_counters` op. One op rather than `remove_counters` beside `add_counters`, because modular moves **all** of them and the number is not knowable when the card is written; two ops would thread the count through a binding nothing sets. The amount is clamped to what is actually on the source, and a move with no destination takes nothing off it. The default source is *this permanent wherever it is*, deliberately not the `{"self_only": true}` selector, which resolves through a battlefield scan and finds nothing for the modular creature that has just died |
| **Counters a dead creature had** | "…if it had no -1/-1 counters on it" — persist and undying. `counters_on` cannot answer it: `reset_permanent_state` empties `counters` on the way to the graveyard, so asked after the death it is always zero and both keywords would recur for ever. The counts are snapshotted onto the dies event beside `was_creature` and `was_attacking`, which are there for the same reason, and read back as `{"counters_had": "-1/-1"}`. `return_from_graveyard` grew a `counters` spec for the other half, which is the loop guard rather than decoration |
| **Damage history** | "Whenever a creature dealt damage by this creature this turn dies" — a per-turn ledger of victim → sources, cleared at cleanup with the damage itself, read by a `damaged_by` trigger filter. On the state rather than the object, because the creature it asks about has just died |
| **The per-turn ledger** | "If a creature died this turn", "if you attacked this turn", "if an opponent lost life this turn" — six tallies in one `GameState.turn_ledger`: creatures died (by controller), the creatures each player attacked with, damage taken, life lost, spells cast, and cards put into graveyards. None is answerable from the board, because each is a count of an *event* and the board keeps no record that one happened. Folded in `GameState.emit` rather than counted at six primitives: every tally counts something already being logged, and `emit` is the one function all of them pass through, so no emitter changed and none can route around it. Damage to a player counts as life lost as well as damage (rule 118.2), which is what makes spectacle fire off a burn spell. Cleared at cleanup with `damage_ledger` — unlike the draw tally, nothing here can happen before turn 1 |
| **Which creatures attacked this turn** | "Untap all creatures that attacked this turn" (Relentless Assault) and "if you attacked with three or more creatures this turn" (Windbrisk Heights) — the per-*object* half of the attack record, and neither card can be written from the per-player half. `attacked` was a `set[int]` of seats, which is the whole of raid and is 1 whether you swung with one creature or ten, so a `cmp` against 3 could never be true and relaxing it to 1 turns a hideaway land into a raid land. `attacking` is the other near miss and is strictly live combat state: `end_combat` sets `state.combat = None`, and both cards are used in the main phase *after* the combat they are talking about, so it matches nothing there. `tapped` is wrong in both directions — it catches a creature tapped for mana and misses a vigilant attacker, which is the one Relentless Assault most wants to untap. So `TurnLedger.creatures_attacked` maps player id to the **oids** they declared, folded from `ATTACKERS_DECLARED`'s own payload in `emit` like every other tally, and `attacked` is now *derived* from its keys so raid and this cannot disagree. Oids rather than a recount of live permanents because **an attacker that died in combat still attacked** (506.4 — leaving combat does not undo a declaration), which is exactly the case a `{"count": {...}}` over the battlefield gets wrong. Two readers, no new condition vocabulary: the selector key `attacked_this_turn` and the value `attackers_this_turn` |
| **Draw history** | "Add {C} for each card you've drawn this turn" — a per-turn tally of draws per player, incremented in `draw_cards` so nothing routes around it, read as the `cards_drawn_this_turn` value expression. Cleared by the **untap step** and not by cleanup: the opening hand is drawn before turn 1 exists, and cleanup can still hand priority back inside the turn it is ending |
| **Exile until it leaves** | "Exile it until this permanent leaves the battlefield" — the O-Ring family, and **champion**, which is the same mechanism with a sacrificing `else` in front of it. A link written on the *exiled card* naming the permanent that exiled it, so the exiler's own leaves-trigger returns its victims and nobody else's. **Imprint** is the same link read from the other end: an imprint permanent finds *its own* card with `exiled_with: "self"`, and `copy_permanent` takes any object rather than a battlefield one, so nothing new was needed for it -- `controller: "any"` still is, since an exiled card keeps its last controller and the selector default would work by accident |
| **Cost reduction** | Both directions: "This spell costs {X} less to cast" as a card-level field (Ghalta), and "Creature spells with flying you cast cost {1} less" as a `spell_cost_reduction` static discounting *other* cards, filtered on the printed face of the spell being cast. Both go through one function, so legality and payment cannot disagree |
| **Conditional and variant-scoped cost reduction** | "This ability costs {3} less to activate **if** you're the monarch" (Crown of Gondor) and "costs {X} less to cast **this way**" (a flashback rider). One reduction language in `costs.reduction_amount` — a flat `amount`, a `count`, or Ghalta's `total_power`, any of them gated on a `condition` — read from three places: the card-level field, an activated ability's `Cost.mana_reduction`, and a graveyard cast's `Cost.mana_reduction`. The conditional half is not expressible as a `count`, which multiplies a headcount and has no boolean; the variant half cannot live on the card, because the card-level field is variant-blind by design and would discount the printed hand cast as well. The condition is restricted to the heads answerable *before* the spell is on the stack, so a discount clause that could never fire is a load error rather than a quiet nothing |
| **Ability locks** | "Its activated abilities can't be activated this turn", covering mana abilities |
| **Transforming double-faced cards** | Two `CardDef`s and one `GameObject`: `transformed` picks which face `GameState.card_of` returns, which is a single choke point, so the layers, legality, combat and the serializer all follow with no changes of their own. Enters front face up (712.13a). A back face is never cast, drawn or put in a deck, and the front→back link is authored while back→front is derived. Both faces share one Scryfall id and differ by `CardArt.back`. **Modal** double-faced cards are still absent — a back face here is a face, not a second castable card |
| **Split second** | "As long as this spell is on the stack, players can't cast spells or activate abilities that aren't mana abilities" (702.61a). Priority is **not** suppressed — players still get it and still pass; what is withheld is almost everything they could do with it. Skipping the window instead would also skip state-based actions and trigger draining. Mana abilities survive because the rule says so, filtered out of the full activated list rather than re-derived; special actions (playing a land, suspending) survive too, being neither casting nor activating. Read off the stack rather than latched at cast time, so it ends exactly when the spell leaves — countered, resolved or fizzled alike |
| **Activation restrictions** | "Activate only if you control five or more Vampires" — a `condition` on an activated ability, in the full `if`-effect language, checked by `legality` before the ability is offered and nowhere else (602.5c). Distinct from `sorcery_speed_only`, which is a timing restriction rather than a board one |
| **The top card of a library** | Both halves of Vampire Nocturnus: `reveal_library_top`, a player-wide static that changes no rule and only makes one card public (sent to every seat, since "revealed" means revealed), and a `top_of_library` condition leaf reading that one card's printed face. A pipeline input like any zone count — and a strictly sharper question than `exists` over the library, which asks whether *any* black card is anywhere in ninety-nine |
| **Extremes, and event bindings in an intervening if** | "A creature with the least toughness among creatures you control" — the `extreme` selector clause (bolster), applied after every other clause because an extremum is a fact about the pool rather than about a candidate, and keeping ties so the player still chooses (701.36a). Separately, a trigger's intervening-`if` is now evaluated against **the event's bindings**, not just the board: evolve's "if that creature has greater power than this creature" read zero for "that creature" and never fired, silently. The condition and the ability it gates now build their bindings from one function, so they cannot disagree about what "that creature" means |
| **Relative selectors** | "…for each other attacking creature that **shares a creature type with it**" — `shares_a_type_with` and `exclude_binding`, both naming a trigger binding rather than a list written into the card. Derived subtypes on both sides, so changelings and granted types count; an unbound name matches nothing rather than everything. `shares_a_color_with` is the colour twin and is the whole of **radiance**, with one boundary of its own: a colorless object shares a colour with nothing, itself included, so radiance off an artifact creature hits only the target — and "is not a different colour" inverts exactly that case while looking identical on a board of coloured creatures |
| **Looking at a hand — private information** | "Look at target player's hand" (Glasses of Urza) — the `look_at_hand` op, and the engine's first channel for information one seat holds and the others do not. `reveal` is public by construction, so a card written with it tells the victim's *other* opponents everything as well, which at a pod changes who is ahead. Entitlements live on the card (`GameObject.revealed_to`) rather than in an event, because `player_view` is rebuilt per request and has to answer "may this seat see this?" indefinitely; it sends them to the one seat under `hand_revealed`, and every other seat still gets `hand: null` and a count. Cleared by `reset_permanent_state`, so a card that leaves and returns is hidden again, and a card drawn after the look was never seen. The server needed no change — `state` passes `player_view` through untyped |
| **Counting an ability's own resolutions** | "If this is the second time this ability has resolved this turn" (Scythecat Cub) — `{"resolutions_this_turn": "self"}`, a seventh tally in `TurnLedger` and the only one keyed by `(object, ability index)` rather than by player, because "this ability" is not a fact about a seat and two copies count separately. Also the only one not folded in `GameState.emit`: `ABILITY_RESOLVED` fires *after* the effects, one resolution too late, so `resolve_top` bumps it on the way in — past the fizzle (608.2b) and intervening-if (603.4) returns, neither of which resolves, and before the effects, so the card counts the resolution it is in. `set_flag` could not stand in: it is one-way, so a mark from the first landfall would persist across turns and double the third resolution too |
| **Searching two zones as one pool** | "Search your library **and/or** graveyard for a creature card … and put it onto the battlefield" — the `search_zones` op. The count is over the union, which is the whole of what "and/or" means: a `search_library` followed by a `return_from_graveyard` carries a count each and fetches up to two creatures, and `choose_mode` gets the count right but makes the choice blind and locks out the other zone. `search_library` is now this op with one zone, so they cannot drift apart. Each half is matched in the zone it came from, and a `zone` in the selector is refused rather than silently overridden |
| **Looking at the top N** | "Look at the top twenty cards of your library, put any number of land cards from among them onto the battlefield tapped, then shuffle" — the `look_at_top` op. `search_library` was the only thing that could put a land from a library onto the battlefield tapped, and it sees the *whole* library, so Through the Forest Gate written with it is a tutor rather than a gamble. Not a search, and the two differences are the ones that would be silent if wrong: nothing shuffles unless the card asks (701.19c's shuffle belongs to searching a hidden zone; the cards you declined stay on top, in order), and `amount` is required rather than defaulted. The count is the ordinary selector `count` on `objects`, since `pick_from_pool` is shared with `choose_objects` |
| **A library position, not a library end** | "Put target nonland historic permanent into its owner's library **fourth from the top**" (Lost to Legend) — `put_on_top`'s `from_top`, the printed ordinal counted from 1, plumbed to `move_object` as `to_index`. The zone layer had exactly two library positions, `insert(0)` and `append`, and a depth rounded to either is a different card: on top the owner redraws it next turn, which inverts what the depth buys, and on the bottom of a 99-card deck it is exile with extra steps. Three things are only visible when wrong and each is pinned in `tests/unit/test_library_depth.py`: the **ordinal** (fourth is index 3, and third is a turn early), the **clamp** (a short library takes it at the bottom — and the *floor* matters as much, since a raw negative index counts back from the bottom and would bury a card asking for the top), and the **owner** (`obj.owner`, never the controller; only a stolen permanent can tell, and there the controller's library keeps the victim's card for good). `to_index` is optional and library-only, so the thirty-odd existing `move_object` callers are untouched, and no expectation key can read a library's *order* — the authoring gate can prove the card left the battlefield and landed in its owner's library, and nothing more |
| **"Any number of"** | A selector `count` of `"any"`: the chooser takes a free subset, from none of the pool to all of it. The third of three spellings and a genuinely different card from the other two — `"all"` is mandatory, and a value expression forces exactly that many because the one number became both the minimum and the maximum of the question. Last March of the Ents is the witness: with only the old forms it emptied your hand or demanded a count fixed when the card was written. Nothing below the decision layer was missing — `ask_objects` always took distinct `min_count`/`max_count` bounds — so this is a spelling, not a mechanism. Refused at load time alongside `random` or `chooser: "none"`, both of which resolve the whole pool without asking and are `"all"` under another name |
| **One-shot type changes** | "It becomes a Vampire in addition to its other types" — the `add_subtype` **op**, distinct from the static of the same name: written onto one object and outliving the permanent that converted it. Recorded on the object, so a static's filter may read it without any static coming to depend on another's output |
| **Gaining control** | "Gain control of target creature" — permanently, via the `gain_control` op. The object never changes zones, so it is `controller` plus the three rules hanging off it: summoning sickness for the new controller (302.6), removal from combat (506.4), and zone destinations that still follow the **owner** (400.3). Its own `control_changed` event, because no zone change happens and the log would otherwise show a creature swapping sides in silence. The until-end-of-turn form (Act of Treason) is **not** implemented and the loader refuses a `duration` rather than ignoring it |
| **Monstrosity** | The counters, the one-way flag, and the "becomes monstrous" trigger |
| **Conditional statics** | "As long as this has a slumber counter on it, it's a land" — including type *replacement*, not just grants. The condition is a boolean tree (`all`/`any`/`not`/`exists`/`cmp`/`is_your_turn`) over counters on the source, printed characteristics of the board, and how many cards sit in a zone, so **Threshold** works: Nimble Mongoose is a 1/1 at six cards in the graveyard and a 3/3 at seven, in either direction |
| **Trigger doubling** | Ancient Greenwarden's "that ability triggers an additional time", for lands entering |
| **Hybrid mana** | `{W/U}` and `{2/W}` parsed, paid and counted towards colour identity |
| **Restricted mana** | "Spend this mana only to cast a creature spell", by filtering sources before the solver |
| **Detain** | "Until your next turn, that permanent can't attack or block and its activated abilities can't be activated" (701.30a) — one op, because detain is one printed word and the residual gate asks each *ability* which sentence it implements. Recorded as the **player** who detained rather than a turn number: "your next turn" moves when somebody is eliminated, so the untap step clears the detain belonging to whoever is untapping. Not a `TempEffect`, for the reason `must_attack` is not — `until_eot` is wiped at cleanup, and a detain that ended there would expire before the creature would ever have attacked |
| **Block requirements** | Provoke: "target creature blocks this creature this combat if able" — the `must_block` op, an oid on the blocker naming the attacker it owes, spent when blockers lock in. The mirror of `must_attack`, and it stops being a mirror at the enforcement point: attacking is not exclusive, so withholding "Done attacking" is enough, while a blocker that blocks the wrong creature cannot be retracted. So a block requirement narrows what `legal_blocks` **offers** as well as what `blocks_valid` accepts. Always "if able", checked with `can_block(..., ignore_existing=True)` — a creature that chose to block elsewhere was able to block this one, which is the whole thing provoke prevents |
| **Per-player attack restrictions** | "You can't attack that player this turn" (Call for Aid); "they can't attack you this combat" (Champions of Minas Tirith) — the `cant_attack_player` op, taking an **attacking** player, a **defending** player and a duration of `this_turn` or `this_combat`. The engine's other attack prohibitions are all facts about one creature, and `attack_forbidden` matches its filter against the attacking creature with no defender in the question at all, so this needed a legality seam rather than a stronger filter: `combat.attack_target_forbidden`, with `legal_defenders`/`legal_planeswalker_defenders`/`add_attacker` all taking the attacking oid and routing through it. Kept on the **table** (`GameState.attack_restrictions`) beside `monarch`, because it is a fact about a pair of *seats* and a resolving sorcery leaves no permanent to own it — a `TempEffect` is a list on an object and had nowhere to put it. Both printed shapes are one op with the two player fields swapped, which is why neither is inferred as "the other one". Planeswalkers are **exempt**: attacking a planeswalker its controller is not attacking that player (506.2), which is the Ghostly Prison ruling. `duration` is required rather than defaulted, because `this_combat` read as `this_turn` gives an extra combat away free and the reverse blanks it. **Not implemented**: `goad`, which wants the same seam with the opposite planeswalker answer |
| **Attack requirements** | Both forms: the one-shot `must_attack` op ("attacks this turn / next combat if able") and the continuous `attacks_if_able` static ("attacks each combat if able", including the goad-shaped "creatures your opponents control"). Enforced at one point by withholding "Done attacking", and always subject to "if able", so a tapped or summoning-sick creature owes nothing and the step cannot deadlock |
| **Variable mana abilities** | "Add {G} for each +1/+1 counter on this creature" / "for each creature you control" — an `amount` on `add_mana`, evaluated at activation and applied at the one point the payment solver and the payout already share, so the price offered and the mana made cannot differ. Rule 605 is intact: evaluating the amount asks nothing, it only looks |
| **Token copies** | "A token that's a copy of target creature", copying the printed card and nothing accumulated on it |
| **Protection** | From a type, subtype or colour, across all four of damage, enchant/equip, block and target |
| **Permanent keyword grants** | `grant_keyword` takes a `duration`: until end of turn (the default, unchanged) or `permanent`, meaning for as long as the permanent lasts. Riot's "enters with haste" is the second, and the difference is invisible on the turn the creature arrives and total afterwards — an until-end-of-turn haste evaporates at cleanup, leaving a riot creature that chose haste indistinguishable from one that chose the counter. Stored in `granted_keywords` rather than as a `TempEffect`, for the reason `hasted_by_suspend` is a field: only one of the two is swept by `clear_until_eot`. A misspelled duration is refused rather than defaulted |
| **Keyword counters** | "A keyword counter is a counter with a keyword ability's name, and a permanent with one has that keyword ability" (122.1c) — a vigilance counter, a lifelink counter, an indestructible counter. No new op: `add_counters` always accepted the kind, and what was missing is that the characteristics pipeline read only `+1/+1` and `-1/-1`, so the clause resolved into a tally nobody consulted and the creature was exactly as tappable as before. Read in the **keyword-grant layer**, not beside the `+1/+1` counters five layers later; the real layer system makes the same split (613.1f against 613.1d) and for the same reason — one counter is an ability and the other is a size. The set is derived from `Keyword` rather than listed, since 122.1c names no subset, minus `INERT_KEYWORDS` (a partner counter could grant nothing). Not `grant_keyword`, which hands the keyword over with no object: a counter is separately visible to `counters_on`, `remove_counters`, `move_counters` and `proliferate`, outlasts the turn, and has no link back to whatever placed it. The one thing the loader adds is a refusal: a kind that *normalises onto* a keyword without being spelled as one (`"Vigilance"`, `"vigilance counter"`, `"first strike"`) is a load error rather than an inert clause that prints as the card does |
| **Granted abilities** | "…and 'Whenever this creature deals combat damage to a player, draw a card'", until end of turn. Triggered abilities only |
| **Retrace** | Casting from the graveyard by discarding a land |
| **Suspend** | The special action, the upkeep tick, the free cast, and haste on what arrives |
| **Splitting into piles** | Fact or Fiction: an opponent splits, the caster chooses |
| **X costs** | The caster chooses X, as a `choose_x` decision raised before the cost is paid. Legality still computes the ceiling, but only to decide whether the spell is castable at all |
| **Manual mana** | A seat may tap its own permanents and pick which colour a modal mana ability makes. Mana abilities never use the stack, so this keeps priority |
| **Modal spells at cast time** | A single top-level `choose_mode` is answered as the spell or ability goes on the stack, and recorded on `StackItem.modes` |

## Simplified

Each of these is a deliberate trade. The rationale matters more than the rule.

| Simplification | What it means | Why |
|---|---|---|
| **No layers system** | Continuous effects apply in a fixed order; static filters and static "as long as" conditions read pipeline *inputs* only — printed characteristics, board state, counters, zone counts — never another static's output, enforced at load time | The full layer system with timestamps and dependency analysis is a large subsystem that would change no outcome for any card in these decks |
| **Automatic mana payment, by default** | The solver picks which land to tap, preferring to spend abundant colours so scarce ones stay open. A land doubled by Vorinclex doubles what it produced rather than offering a free choice of type, because a mana ability may never stop to ask. A seat can opt out with **manual mana** (`PlayerState.manual_mana`, the rail's Auto mana / Manual mana toggle), which offers every tap-only mana ability as an action and one action per colour a dual could make. Off for AI seats, so the RL action space is unchanged. Independently of the toggle, a permanent that offers something *besides* its tap-only mana ability offers both to a human seat (`PlayerState.offer_all_abilities`): a Forest stays the solver's, a Mind Stone shows its sacrifice ability *and* its tap | Removes an enormous branching factor for the RL agent and the worst tedium from the UI, without making "tap this land for blue" impossible to say — or letting one click spend a permanent that had more than one thing to do |
| **Which same-coloured mana gets spent** | The pool records, pip by pip, which permanent made each mana, so "when that mana is spent" is answerable. Which of two identical pips a payment consumes is the player's choice at a table; `ManaPool._take` pops newest-first | Payment taps what it needs immediately before spending, so the newest pip is the one just made for this spell — which is the only case Path of Ancestry or Opal Palace is ever played for. Asking would put a decision inside cost payment, which is where mana abilities are forbidden to stop |
| **A reflexive trigger resolves inside its own ability** | "You may sacrifice a Vampire. **When you do**, Sorin deals 3 damage to any target" is written as a `may` with a sacrifice `pay`, so the payload runs in the same resolution instead of going on the stack as its own object. The option is still withheld when you control no Vampire, and the payload still runs only if the sacrifice completed | Same trade as delayed triggers and mode-before-target above: observable only to somebody who would respond differently to the reflexive half than to the ability that scheduled it. What it costs is the response window between the sacrifice and the damage, and the targets being chosen at activation rather than when the reflexive half would go on the stack — which never gates activation, since a player is always a legal "any target" |
| **Gate 5 cannot witness a loyalty ability** | The authoring harness casts a card and stops at the first priority window; it never activates anything. So a planeswalker's abilities are checked by the vocabulary and text-attribution gates alone, and its starting loyalty is the only thing the behaviour gate can assert | Making ability bodies falsifiable means teaching the harness to activate them, which is a different piece of work. `tests/unit/test_planeswalkers.py` is what holds the chassis; a card's own abilities are held by the same gates every other card's activated abilities are |
| **Automatic damage assignment order** | Blockers are ordered by effective toughness ascending; the attacker is never asked | One more decision point per combat for a choice that is nearly always forced |
| **`search_zones` always searches every zone it names** | Finale of Devastation prints "If you search your library this way, shuffle". The `if` is there because a player at a table may announce they are searching only the graveyard; `search_zones` always offers both zones as one pool, so it has always searched the library and always shuffles | Making it conditional means asking which zones to search *before* showing the pool, which is a second decision on a card that has none, and it would undo the one thing the op exists for — that "and/or" lets you see both before committing. The only reachable difference is a player who would decline the search to keep a stacked top of library, and they give up the union to do it |
| **Automatic trigger ordering** | Simultaneous triggers you control resolve in a fixed order rather than one you choose | Matters only for a handful of interactions, none of them in these decks |
| **Modes chosen before targets** | A modal spell now picks its mode as it is cast (rule 601.2b), but its *targets* are enumerated as part of the action, so they are chosen first — the reverse of the printed order. A **nested** `choose_mode`, and any `choose_mode` inside a **triggered** ability, still resolve late: neither has a single cast-time question to answer | Cast-time modes were the observable half — an opponent can now see the mode they are responding to. Target-before-mode is what the shared `optional: true` idiom in [card-dsl.md](card-dsl.md) exists to paper over, and closing it means moving target enumeration behind a decision |
| **X capped for the policy** | A human is offered every X from 0 up to what the board can pay. The RL policy sees X ∈ 0..9, because `CHOICE_CAP` in `ai/action_space.py` is 10 and `IDX_CHOOSE` sits below `IDX_YES` in the index layout | Raising the cap shifts every index above it and invalidates trained checkpoints, for a ceiling that only bites above ten spare mana |
| **"As this enters, choose…" is a trigger** | Vanquisher's Banner's "as this artifact enters, choose a creature type" is implemented as a `self_enters` trigger, so the type is chosen a moment *after* the permanent arrives rather than as it does. Until it is chosen, the filters it feeds match nothing | `zones._enter_battlefield` applies enter-replacements synchronously and cannot yield a decision. The window is observable only by another trigger ordered between the two, and closing it means making the replacement whitelist generator-driven |
| **Object identity survives zone changes** | The `oid` is preserved where the rules would create a new object; permanent state is reset instead | Simpler and equivalent for everything except effects that track "the new object" |
| **Last-known information is explicit** | A card that needs a value after its target has left declares a `snapshot` op (see Swords to Plowshares) | A global LKI system for two cards is not worth it; the explicit form is also easier to read |
| **Commander replacement is automatic** | A commander always returns to the command zone rather than being asked | It is what players choose in practice, and it keeps zone changes out of the decision system |
| **Legend rule keeps the newest** | Duplicated legends are resolved without asking the controller | The choice is nearly always irrelevant |
| **Target options capped at 12** | A spell offers at most 12 target combinations | Only bites on very wide boards; without it a single "target creature" can flood the action space |
| **Turn cap** | 30 turns per player (60 in a duel, 120 in a pod), then a draw | Self-play must terminate. Draws are counted and reported |
| **Trigger loop guard** | More than 200 triggers in one step raises `RulesLoopError`, scored as a draw | One pathological board must not abort a 10,000-game run |
| **Extra phases capped at 20 per turn** | Grants past `MAX_EXTRA_PHASES_PER_TURN` are dropped rather than queued | "Untap all creatures you control; there is an additional combat phase" plus enough mana is a real printed infinite combo (Aggravated Assault), and the rules let it run for ever. Twenty is far past anything a game turns on, and an unbounded turn is a hung process rather than a loss |
| **Delayed triggers resolve off the stack** | "At the beginning of the next upkeep, draw a card" runs as the step begins rather than being put on the stack | Same trade as modes and trigger ordering: only observable when somebody would respond differently to the delayed half than to the spell that scheduled it |

### Simplifications *inside* a hand-written card

Everything above is a deliberate, engine-wide trade. There is a second kind that
was never decided and never written down: individual precon cards that implement
less than they print.

`data/decks/*.deck.json` records `substitutions` — Scute Swarm swapped for
Tireless Provisioner because copy effects did not exist. That mechanism only ever
covered swapping one card for another. It has nothing to say about Tireless
Provisioner itself dropping the Food-or-Treasure choice, Krosan Tusker shipping
as a vanilla 6/5 with no cycling, or Anticipate being implemented as Preordain.

Those cards predate the authoring pipeline and never cleared its gates. The
current count is in `tests/cards/precon_deficits.json`, which is generated, and
the whole picture is `python scripts/audit_cards.py`. They are not new bugs —
they are the cost of building the precons before the gates existed, measured for
the first time. Repair one with `/author-cards <name>`; the mechanics they are
waiting on are `/extend-dsl` jobs, and as of this sequence there are none left
in the report except Kydele's per-turn draw tally. Cycling was
one of them and now ships in full, trigger included, so Krosan Tusker is off
this list. Evolve went with it, on Gyre Sage. Skulk and threshold have both shipped since, and
Nimble Mongoose is off this list. So are intimidate (with the rest of the
evasion family) and investigate — the latter needed no vocabulary at all, only a
Clue in the token pool, and Bygone Bishop is off this list with it.

## Imported cards, which are simplified further

Everything above describes a **hand-written** card. A deck imported from Moxfield
is mostly cards nobody wrote rules for, generated by `src/automtg/cards/proxy.py`,
and those carry a second, much larger set of simplifications. Each is recorded on
the card and shown at import; the full list is in
[deck-import.md](deck-import.md). The ones that change how a game plays:

| Simplification | What it means |
|---|---|
| **Non-keyword rules text is inert** | The card is a real permanent with the right name, cost, types and stats. Its printed abilities do nothing |
| **Front faces only** | A transform or modal DFC generates as its front face. An MDFC land loses the land half |
| **Phyrexian and snow costs are rewritten** | `{W/P}` becomes `{W}`, `{S}` becomes `{1}`. Mana value is always preserved. Ordinary hybrid (`{W/U}`, `{2/W}`) is now kept exactly as printed |
| **No loyalty, no defence** | Planeswalkers and Battles enter play and then sit there |
| **One mana per activation** | Scryfall records *which* mana a permanent makes, not how much. A generated Sol Ring taps for one |
| **Some taplands are unconditional** | "Enters tapped unless…" is now read exactly for the three printed shapes that carry the cycle — a basic land subtype test ("a Mountain or a Plains"), a count of other lands, and a count of basic lands — so checklands, slowlands, fastlands and battle lands are the cards in the deck list. The shapes still not read ("unless you have two or more opponents", "unless a player has 13 or less life") enter tapped unconditionally. That fallback direction is fixed on purpose: generating the *upgrade* would hand every imported deck a better mana base than it was built with |
| **`*` power reads as 0** | The characteristic-defining ability behind it is not modelled |
| **Some lands do nothing** | A land whose whole ability the generator cannot express — a bounce land's "return an Island you control" — arrives as an inert permanent. The import report counts those separately from the ones that simply make no mana, because a fetchland makes no mana *by design*. Fetchlands and creature-lands themselves are now [authored](card-authoring.md) rather than generated |

## Not implemented

These are absent, and the curated decks avoid them. Adding any one is additive.

**Card types and mechanics**
Planeswalkers · battles · sagas · companions. **Vehicles** and **face-down
creatures** are implemented (crew, morph, manifest). **Transforming** cards are
implemented (above), and so are **split cards, adventure and aftermath** — one
card with a `second_face` that is *cast* rather than turned over to. **Modal
double-faced cards** are the same mechanism with a permanent on the other side
and no rider on where the card goes, so nothing in the engine refuses one; no
shipped card exercises it, so it is untested rather than implemented. **Fuse** ("you may cast one or both halves")
is implemented as a third cast line built from both halves at once.  **Partner** is accepted as an inert
keyword: it is a deck-construction rule, and the engine is handed a finished deck

**Costs and casting**
Alternative costs in general (evoke is implemented) · phyrexian and snow mana ·
convoke and similar · overload

**Effects**
Copying a permanent as anything but a token · gaining control of a permanent
*temporarily* (the permanent form is implemented; Act of Treason is not) ·
damage *redirection* (prevention is implemented -- see absorb) ·
granting a *static* or *activated* ability to
another permanent (triggered ones work) · general replacement effects (the whitelist is
four enters-the-battlefield forms; the three that *ask* -- dredge, madness,
miracle -- are implemented separately in `engine/replacements.py`)

**Combat**
Attacking planeswalkers or battles · manual damage division · attacking with
creatures you do not control.

*Manual damage division* means the **ordinary** case: with no banding involved,
the engine sorts the damage assignment order by effective toughness and asks
nobody. That is a real divergence — the attacking player is entitled to that
order — and it stands.

**Banding is implemented**, and the reason it could be is that the divergence
above is about *who is asked*, not about a missing concept. See its own row.

**Structural**
Multiplayer politics (voting) · sideboards and companions · **the initiative**
and the other designated-player mechanics. The city's blessing, **day/night**
and **the monarch** are implemented — see the monarch's own row above, which is
the field day/night introduced with rule 721.3's two inherent triggered
abilities hung off it. The initiative is the same shape with different rules
(it moves on damage to the *permanent* holding it, and it walks the Undercity),
and no card in the pool prints it, so it is unbuilt rather than blocked

## How this is enforced

None of the above is a promise in prose — it is checked:

- The card loader validates every op name, selector key, value form, keyword, type and
  trigger event against the registries. An unknown one raises `DslError` at load time,
  which fails `pytest`, not a game.
- The "statics may not read statics" constraint is a load-time check on every static
  ability's filter.
- `tests/cards/test_every_card_works.py` plays every shipped card in a rigged sandbox
  and asserts it resolves into the right zone, with per-card outcome expectations from
  `tests/cards/expectations.json`.
- `tests/cards/test_hand_written_cards.py` runs all six authoring gates over every
  hand-written card, and separately checks that each card's `oracle_text` is what the
  catalog says it prints — the check that stops a card from being verified against a
  summary of itself. Cards that do not pass yet are listed, with reasons, in the
  generated `tests/cards/precon_deficits.json`; that list can only shrink.
- `tests/cards/test_auto_cards.py` does the same for every machine-authored card.
- Deck legality, colour identity and singleton rules are tested per deck.

If a card in this repo does not work, one of those tests fails.
