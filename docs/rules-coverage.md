# Rules coverage

This is the honest artifact. It says what the engine does, where it takes a shortcut,
and what it refuses to model at all. If you want to know whether this engine can
handle your card, read this page.

The short version: **everything the two shipped decks need is implemented and tested.**
The simplifications below were chosen so that removing them later is additive work,
not a rewrite.

## Implemented

| Area | Detail |
|---|---|
| **Turn structure** | All 13 steps, turn-based actions, correct priority windows, cleanup repeating per rule 514.3a, and **additional phases** — see below |
| **Additional combat and main phases** | "After this main phase, there is an additional combat phase followed by an additional main phase" (506.1, 505.1b). `Step` is an ordered `IntEnum` walked one integer at a time, so a repeated phase had no representation — and needs none, since an extra phase is the same steps entered again. What has to be remembered is only that the phase the turn was *about to* enter is still owed: `GameState.extra_phases` queues the phase kinds a card granted and `resume_step` is the one bookmark the turn comes back to. So an extra combat granted in a precombat main is *inserted* in front of the combat the turn already had rather than eating it, and Combat Celebrant's extra combat returns to the bookmark rather than falling through into a postcombat main it never granted. The queue is read only when a main or combat phase ends, which is what makes "after this main phase" right for an Aggravated Assault activated in an upkeep; an unspent grant expires at the turn boundary. The additional main phase is a `POSTCOMBAT_MAIN` step (505.1b) and fires the per-phase `postcombat_main` trigger, and it is not an extra land drop, because `lands_played` is reset by the untap step |
| **"At end of combat"** | The fifth `delay` step, beside `upkeep`, `draw_step`, `begin_combat` and `end_step` — Flamerush Rider's "exile the token at end of combat", a delayed trigger created by the attack trigger's resolution rather than a standing ability. `Step.END_OF_COMBAT` always existed and the turn always walked through it; only `turn.DELAY_STEPS` could not name it. What made this more than a table entry is that it is the **one delay step that is not once a turn**: `extra_combat` gives a turn two or three combat phases, so a step name no longer picks a moment. It means the end of the combat the delay was created in (603.7), and the end of the next combat to begin when there was none — which is `GameState.combat_number`, a monotonic count of combats begun, stamped onto the `DelayedTrigger` at `op_delay` and compared at `turn._delay_due`. `CombatState` cannot carry that identity: `end_combat` throws it away as the END_OF_COMBAT step begins, which is before any delay is read. Substituting `end_step` is a real behavioural difference and not a rounding error — the token would survive the whole postcombat main phase and could attack again in the extra combat, which is what the printed line exists to stop. **Today the stamp changes nothing observable**, because every combat that begins reaches its own end of combat step before a later one does, including one nobody attacked in; it is what keeps that a statement rather than a coincidence |
| **Priority** | APNAP order, retaining priority after acting, auto-pass when passing is the only option |
| **The stack** | LIFO resolution, responses, countering, fizzling when every target became illegal, and **"unless its controller pays {N}"** — the `{"controller_of_target": "t1"}` player spec, which bills the seat holding the *targeted* spell (109.5) rather than the seat that made the demand. Read at resolution, so control of the spell changing while the ability waits moves the bill (608.2). Writing `{"target": ...}` there instead is a **load error**, not a shrug: a spell's ref is not a player ref, so it resolved to nobody and `op_may` billed its own controller — the card played as its own opposite and raised nothing. Also **leaving the stack without being countered** — "Return target spell to its owner's hand" (Reprieve), the `return_spell_to_hand` op. Rule 701.5a makes countering one specific action, so this is stopped by nothing that stops a counter, puts the card in its owner's *hand*, and fires no `SPELL_COUNTERED`; a copy of a spell has no card to return and ceases to exist instead (706.10, 704.5e). It is a separate op because `counter`'s destination is not a parameter and `return_to_hand` cannot see a spell at all — a `kind: "spell"` target is a stack ref, which an `objects` selector drops, so the obvious card silently returned nothing. The loader refuses both misspellings |
| **Casting** | Timing restrictions (sorcery speed vs instant vs flash), targets chosen at cast time and re-checked on resolution |
| **Mana** | Cost parsing, mana pools emptying per step, automatic payment with a backtracking solver, `X` costs |
| **Reflecting mana, and "any type"** | "Add one mana of any color that a land an opponent controls could produce" (Exotic Orchard, Fellwar Stone) and "…any **type** that a land you control could produce" (Reflecting Pool, Horizon of Progress). The one `add_mana` that names no symbols: its options are a question about the board, so the card records the permanents to ask and `costs.mana_options_of` narrows a static superset when the ability is offered — read by both the payment solver and `activate_mana_ability`, because a spell offered on one colour and paid in another strands the payment mid-cast. It **only looks** — no `ask_*`, no generator, no stack — so it stays a mana ability for 605.1a; narrowing an option list narrows a choice every modal mana ability already had. A reflecting ability never asks another one (two Exotic Orchards facing each other would not terminate), and everything else it finds is asked the *same* question rather than read off its load-time field, or an opponent's Path of Ancestry would tell a Fellwar Stone it could produce all five colours. **"Type" is one word and one whole capability**: 106.1b names six types of mana and colorless is one of them, so `any_type` swaps the five-colour superset for a six-symbol one and keeps the colorless index that the colour-only form skips while polling the board. Only the *vocabulary* widens — same selector, same recursion, same skip — so a Pool beside a lone Forest still taps for `{G}` and not for `{C}`, and the unconditional any-type land (a `choose_mode` over six modes) stays refused. **Not modelled**: the template tier still reads only the printed word "color", and a qualified noun ("a *basic* land" — Star Compass, "a *Gate*" — Plaza of Harmony) is a different set of permanents that neither tier guesses at |
| **Imprinted mana** | "{T}: Add one mana of any of **the exiled card's colors**" (Chrome Mox) — `colors_of` on the `add_mana`, a selector over the *cards* whose printed colours are offered. The fifth and only spelling that reads a characteristic of a card rather than what some permanent could produce, and the reason it is not `reflecting`: that key asks each matched object's own mana *abilities* what they could make, and an imprinted nonartifact, nonland card in exile has none, so a Mox written that way taps for nothing for ever. Same shape otherwise — a five-colour superset at load time so `solver_taps` and `offerable_mana_ability` see a mana source, narrowed in `costs.mana_options_of` at activation, read by both the payment solver and `activate_mana_ability`. It **only looks**, so it stays a mana ability for 605.1a. **Nothing imprinted offers nothing** and the activation refuses rather than reaching for the superset — the `choose_mode` over five `add_mana`s is the near miss and is *strictly better* than the printed card, tapping for any colour with nothing exiled. Colourless is not a colour (105.1), so a colourless imprint offers nothing either and there is no `any_type` here. The superset is kept out of derived colour identity, or Chrome Mox would be a five-colour card and illegal in most commander decks (903.4). **Not modelled**: the template tier does not read the sentence, so cards of this family are hand-authored |
| **Vivid mana — one of *each* colour** | "Vivid — {T}: For each color among permanents you control, add one mana of that color" (Bloom Tender) — `each_color_among` on the `add_mana`, the **sixth** way an ability may name its colours and the only one whose output is a bundle instead of a choice. The other five hand `costs.mana_options_of` a list of one-mana options and let the payer pick; this hands back exactly **one** option, a multi-symbol tuple built from the distinct colours of whatever the selector matched, so a three-colour board taps for three mana with nothing asked. One option is the rule and not a shortcut: `legality._mana_option_indices` offers one chip per option and the solver picks an index while planning, so a list here would ask a question the printed card never asks (605.1a). `colors_of` over the identical selector is the near miss and is **Mox Amber** — one mana of a colour the payer picks, so a three-colour board would tap Bloom Tender for one; `reflecting` over the same selector asks a different *question* entirely, polling each permanent's mana abilities, so beside a Forest and an Island it offers {G} or {U} where this key sees neither (a basic land is a colourless permanent); and `add_mana_per` scales one literal symbol by a selector **count**, adding one {W} per white permanent rather than one per colour — and is not a legal mana effect at all, since `_split_mana_rider` ends the mana half at the first op that is not `add_mana` or `choose_mode`. Colourless is not a colour (105.1), so an all-artifact board adds nothing and the ability is simply not a mana source at that moment. The five-colour superset stays out of derived colour identity, or Bloom Tender would be a five-colour card and illegal in the mono-green decks it is played in (903.4). **Not modelled**: the template tier does not read the sentence, so cards of this family are hand-authored |
| **Combat** | Attacker/blocker declaration, evasion, damage assignment order, simultaneous damage, first and double strike as separate sub-steps |
| **Declaration-wide restrictions** | The restrictions that are judged on the finished declaration rather than per creature (508.1c, 509.1b): menace, Tromokratis' `require_all`, and "can't attack or block alone". Declaration is incremental here and all-at-once in the rules, so each is enforced by withholding "Done attacking"/"Done blocking" while the declaration is illegal, with `combat.drop_illegal_attacks`/`drop_illegal_blocks` retracting what was never legal when there is nothing left to add — the alternative being a step with no legal action in it |
| **Keywords** | flying, reach, trample, deathtouch, lifelink, vigilance, haste, menace, first strike, double strike, defender, hexproof, shroud, indestructible, flash, the six landwalks (five basic types plus nonbasic), skulk, fear, intimidate, horsemanship, shadow, wither, infect, totem armor. `partner` and `choose_a_background` are accepted but inert — see below. Every Magic keyword, routed to a mechanism and marked shipped / free / routed / blocked, is censused in [keywords.md](keywords.md) |
| **Triggers** | ETB, dies, leaves-the-battlefield, landfall, land-played, spell-cast, attacks, blocks, combat damage to a player, upkeep, draw step, begin combat, end step, life gain, counters placed, draws, discards (every one of them: a discard effect, the cleanup trim to hand size, and a cycling cost), damage dealt to a permanent (enrage — the event was always fired and nothing subscribed to it; the subscription is scoped to the *victim*, because for this one event the subject and the source are two different creatures), becoming the target of a spell or ability (heroic and ward, fired as it goes on the stack per 603.2d, with the `controller` clause asking whose spell it is rather than whose permanent), becoming blocked or going unblocked (flanking, rampage, bushido, frenzy — a pair told from the attacker's side, both decided when the block declaration closes), and becoming untapped (inspired — the untap step now fires one event per permanent rather than one aggregate with a count). Intervening-if clauses re-checked on resolution. Delayed triggers ("at the beginning of the next end step, …") via the `delay` op |
| **Losing all abilities, and the derived ability list** | "Enchanted permanent is a colorless land with `{T}: Add {C}` and loses all other card types and abilities" (Imprisoned in the Moon). No effect could take an ability *away* before, so nothing had ever needed to ask what abilities a permanent has — five readers each walked `state.card_of(obj).abilities` and got the printed list: `legality._activate_actions`, `costs.mana_sources`, `triggers.collect`, `characteristics._battlefield_statics` and `game._activate`. With a printed list each of those is a separate place for the clause to be forgotten, and forgetting it in any one is a permanent that visibly does nothing and quietly still does something — an imprisoned Sol Ring still tapping for two, an imprisoned Bloodghast still seeing landfall, an imprisoned anthem still pumping. `characteristics.abilities_of` is the single answer and all five ask it; off the battlefield it is the printed list unchanged. **Indices stay meaningful**: `Action.ability_index`, `StackItem.ability_index` and the RL action space all address an ability by position, so a granted ability is *appended* and the list renumbered, and legality and resolution read the same list. A keyword goes with the abilities (113.1a), and the removal runs **before** the grant layers (613.1b) so a Levitation played afterwards and a vigilance counter (613.1f) both still work. Three statics ship with it — `lose_all_abilities`, `set_colors` (nothing could set a colour; `animate` overwrote them as a side effect of a P/T replacement and that was all) and a continuous `grant_ability`, which had to reach legality *and* the payment solver because a granted mana ability nobody can tap is not a mana ability. `set_types` also learned 205.1b/613.1d: the subtypes of a card type it removes go with it, off the `SUBTYPE_CLASS` table derived from the committed catalog, with creature types deliberately absent so an unknown subtype fails safe. **Divergence**: `lose_all_abilities` and the `grant_ability` static are collected off *printed* faces, apart from every other static, because `_battlefield_statics` reads `abilities_of` and `abilities_of` reads them — so gathering both the same way is an infinite regress. The cost is 613.8's dependency analysis, which layers-lite exists not to have: an Imprisoned in the Moon enchanting another one does not switch the second off |
| **An animation with no duration that sets what it becomes** | "Target artifact or creature loses all abilities and becomes a green Elk creature with base power and toughness 3/3" (Oko, Thief of Crowns). `animate` gained `duration: "permanent"` (611.2a: no stated duration lasts indefinitely) and `exact`, and they are separate flags because they are separate facts. The indefinite entry lives on `GameObject.animations`, which cleanup does not sweep and `reset_permanent_state` clears (400.7). `exact` replaces the colours, card types and creature types rather than adding to them, per the card's rulings: an Oko'd Sol Ring is not an artifact and an Oko'd Goblin is not a Goblin, while supertypes stay and an Oko'd legend is still legendary. Non-creature subtypes go with their card type (205.1b), so an Oko'd Forest is not a Forest. The base P/T is still layer 7b, under counters, anthems and pumps. Every animation carries a `timestamp`, and timed and indefinite ones are applied together in that order, so whichever began later sets the base size (613.7). **Divergence**: the layer ordering is still layers-lite. A `set_types`, `set_colors` or `set_pt` *static* overrides the Elk whatever its timestamp, and "loses all abilities" does not take away a keyword granted until end of turn earlier that turn |
| **"Dies or is put into exile"** | Kaya the Inexorable's ghostform: "When this creature dies or is put into exile, return it to its owner's hand and create a 1/1 white Spirit creature token with flying." `leaves_battlefield` takes `to_zones`, checked against the destination `move_object` now puts on every departure event (`to_zone`). `dies` alone misses exile, and the bare event is wider than the card, because a bounce or a tuck would also make a Spirit. An event without a destination fails the clause rather than passing it. The loader allows it on `leaves_battlefield` only, with departure zones only. The return needs nothing new: the card keeps its oid in its new zone, and a `union` of graveyard and exile `self_only` branches finds it. A granted ghostform is heard as the creature leaves through the `left_with` snapshot |
| **Granted static abilities** | "Commander creatures you own have "Creature tokens you control get +2/+2."" (Inspiring Leader). `grantable_abilities` refused a static outright, and the widening needed no new code in the pipeline: `abilities_of` appends the granted ability to the **recipient's** list and `_battlefield_statics` walks that list, so the copy arrives already sourced on the recipient. Everything source-relative inside it then means the right thing for free — the quoted anthem's `controller: "you"` is the commander creature's controller rather than the Background's — and two commander creatures are two entries in that walk, so the tokens get +4/+4 with nothing counting them. The near miss is a `buff` on the Background under an `{"exists": {"is_commander": true}}` condition, and it is a different card three ways: it does not stack per commander creature, it pumps the *Background controller's* tokens, and it does not travel with a commander that changes hands. **Layers-lite is untouched** because a grant changes only which permanent a static is sourced on: who receives it and what it affects are both decided by `_matches` on printed characteristics and board state, and `_ability_statics` still collects `grant_ability`/`lose_all_abilities` off printed faces — the divergence recorded in the row above — so a static granting a static is never collected and is refused by name instead. What may be granted is derived rather than listed: every static read through `_battlefield_statics`. The two families left out are the ability statics and the player-wide ones (plus `replace_token_creation`), whose readers walk printed faces and would never see an appended ability. The one-shot `grant_ability` **op** still may not hand a static over — its grants are pointers `_battlefield_statics` never walks — and `{"chosen_type_of": "self"}` inside a granted filter is refused because it would read the recipient's choice where the author meant the granter's |
| **Granted activated abilities** | "I — This Saga gains "{T}: Add {C}."" and "II — This Saga gains "{2}, {T}: Create a … Construct …"" (Urza's Saga). A one-shot `grant_ability` may hand over an activated ability, mana or not, for a duration or `permanent`ly, and so may the static. Two holes closed together. The op's grants were read only by `triggers.collect`, so an op-granted activated ability was never offered — legality, the payment solver and `game._activate` read `characteristics.abilities_of`, which knew only static grants; the op's *activated* grants are now appended there with their provenance (its triggered ones are not, or they would fire twice). And `stack.ability_of` resolved an activated ability off its source's *printed* list, which is why a granted one was refused unless it was a mana ability (605.3a keeps those off the stack): `push_activated_ability` now records `granted_by` and the index into the granter's `grantable_abilities`, plus the granter's card id for a token that has ceased to exist, so the ability resolves as itself after the grant has left with its source (608.2). On Urza's Saga the printed index would have been chapter II — resolving the wrong ability *and* telling 704.5s a chapter was still on the stack, so the Saga would not be sacrificed after III. A grant ends with the object (400.7). **Not modelled**: a granted activated ability that works from another zone (granted cycling) is refused at load, since a grant lives on a permanent; and `turn_ledger.resolving` keys a granted ability by its granter-pool index, which only a "resolved this turn" condition on a granted ability could tell apart |
| **Mode-owned targets** | "Choose up to two. Return those cards from your graveyard to your hand. • Target artifact card. • Target creature card. • Target enchantment card. • Target land card." (Call Damage Control) — four modes, four *different* targets, two live at once. The gap record filed against this proposed moving all target enumeration behind a decision, which changes casting for every card in the pool. It needs nothing of the sort: `card.targets` stays exactly what it was, and a spec carrying `mode` is simply **not in it**. Legality enumerates cast actions from the card-level list and never sees a mode-owned spec, so every other card is untouched; `Game._ask_mode_targets` declares the chosen modes' targets between 601.2b and 601.2h, which is where the printed order puts them. Three rules come with it. A mode with no legal target is **not offered** (601.2b), so a Call Damage Control cast over a graveyard of creature cards shows one bullet rather than four ways to spend a mode on nothing; a spell that cannot meet its floor is not offered as a cast line at all (`stack.modal_cast_ok`); and refs are stored in **printed mode order**, which `CardDef.specs_for_modes` rebuilds on resolution, because `filter_legal` splits stored refs by position and two orders for one answer is how a ref lands in another mode's bucket. The same card may be targeted by two modes — 601.2c forbids repeating a target within one instance of the word "target", and two modes are two instances. No new `DecisionKind`: `ask_targets` reuses `choose_objects` with `purpose: "target"`, so the RL encoder, the heuristic agent, the client's prompt dialog and the authoring verifier all answer it unchanged. It also closed a live bug in `up_to` modes — choosing *none* is an answer, and without `StackItem.modes_answered` the empty tuple read as "nobody asked yet" and `op_choose_mode` asked again on resolution. **A triggered ability has the same moment** (603.3d, applying 601.2b then 601.2c as it is put on the stack) and now the same vocabulary: `Ability.mode_targets`, `Ability.specs_for_modes`, and the mode and target questions asked in that order by `stack.push_triggered_ability`. Oltec Matterweaver — "Whenever you cast a creature spell, choose one — • Create a 1/1 colorless Gnome artifact creature token. • Create a token that's a copy of **target** artifact token you control" — is the witness, and its first bullet is the whole argument: on the first creature you cast you control no artifact token, so 601.2b withholds the second bullet and the Gnome is still made. An *activated* ability is still refused, because legality fixes an activation's targets before `Game._activate` asks which mode |
| **Command zone** | Abilities that work from the command zone, commander tax, commander damage, the zone-change replacement, and **emblems** (114) — an `emblem` op puts an object with only abilities into the getting player's command zone, where its abilities work for the rest of the game with that player as "you". Both **triggered** (Edgar Markov's eminence) and **static**: `active_zones: ["command"]` on a static is gathered by `characteristics._command_zone_statics`, which `_battlefield_statics` appends so the characteristic layers and the cost reductions see it at once, plus a line of its own in `player_statics._active_player_statics`, which walks the battlefield rather than reading that list. That is The Ur-Dragon's "as long as this is in the command zone **or on the battlefield**" — one static naming both zones, because being gathered from either *is* the "as long as", the same argument Anger makes for the graveyard — and it is what lets an emblem be a static. "Other … spells you cast" is `exclude_self` on a `spell_cost_reduction`'s `affects_spells`, matched by card id, and it matters only here: a commander is cast *out of* the zone its own eminence static is read from. **Not modelled**: an emblem or command-zone **activated** ability, refused at load time rather than loaded inert, because nothing offers an activation from that zone |
| **Static abilities** | Anthems, keyword grants, P/T setting (including `*/*` read off the board), subtype grants, type replacement, "as long as" conditions (a boolean tree over counters, board and zone counts, and whose turn it is — Threshold), "can't block" (unleash — the mirror of `cant_attack`, checked in `can_block` because it is a fact about one creature rather than about the whole declaration, and a static rather than a keyword because it is a permission), and the player-wide ones: extra land drops, no hand limit, playing lands from the graveyard or the top of the library, doubling land triggers, doubling land *mana* (and, Kinnan's half of the same sentence, the mana a **nonland** permanent is tapped for), and freezing the lands an opponent taps — each of which honours an "as long as" condition of its own. A static's filter may also read **`owner`** (`you`/`opponent`), which is not `controller`: 903.3 makes ownership the relation on a commander, so a commander an opponent has stolen is still one you own and one you have stolen is not. Writing it switches the defaulted `controller: "you"` off, which is the only way the stolen case survives, and it is the same spelling `costs`' cost-reduction filter has read since Visions of Glory |
| **"…is the chosen type in addition to its other types"** | Roaming Throne, Arcane Adaptation, Xenograft. `{"chosen_type_of": "self"}` existed only as a **read** — every shipped user of it (Vanquisher's Banner, Cavern of Souls, Urza's Incubator) asks "is that *other* object of the chosen type" — and this family makes a permanent *be* it. So the entry now stands on the **granting** side of an `add_subtype` static as well as inside a filter, substituted in layer 4 inside the loop that already knows which permanent each static came from: it reads the static's **own source**, which is what makes the Xenograft form (pointed at every creature you control) mean anything at all. A source that has chosen nothing grants nothing rather than every type, and choosing again moves the grant, because layer 4 re-reads the source on every recompute — which is precisely what a one-shot cannot do, and why the `add_subtype` **op** refuses the entry at load time instead of learning the substitution. That refusal closed a live trap: the op coerced its list with `str()`, so the same spec inside a `self_enters` trigger compiled clean and the permanent gained the literal subtype `"{'chosen_type_of': 'self'}"` — a card that loaded, resolved, passed a zone assertion and was of no creature type at all. A **granted** static may not carry it either, for the reason a granted filter already could not: a grant moves the source to the recipient, which chose nothing. **Divergence, and it is layers-lite's**: a granted type is in `chars()` and is *not* in another static's filter, because `_matches` reads printed characteristics plus the object's own `added_subtypes` so that no static depends on another's output — so a Xenograft naming Goblin does not put a board of Bears under a Goblin lord's anthem |
| **State-based actions** | All nine listed in [engine-rules.md](engine-rules.md), plus **ten poison counters** (704.5c), and the **Role rule** (704.5y, 303.7a) — of the Roles one player controls on one permanent, all but the most recently attached (613.7e, `attached_timestamp`) are put into the graveyard. Roles are Aura tokens created with `create_token`'s `attached_to`, which creates nothing when the host has left the battlefield |
| **Level up** | "Level up {2}… LEVEL 1-3 3/4… LEVEL 4+ 6/6, flying". Filed as a characteristic-defining subsystem and answered by the second half of its own census line: a band **replaces** the printed P/T rather than adding to it, which is `set_pt` and not `buff`, and a band is an interval, which a static's condition already says with `all` over two `counters` comparisons. What is left is a level counter (an ordinary counter) and an ability that adds one (an ordinary ability). The pipeline already runs `set_pt` and `grant_keyword` after reading a static's condition, and a counter is a pipeline input, so nothing here is characteristic-*defining* in the sense that would need a subsystem — and `+1/+1` counters still layer on top of the band, which is the correct order |
| **Epic** | "For the rest of the game, you can't cast spells. At the beginning of each of your upkeeps, copy this spell except for its epic ability" (702.50a). Both halves are about where the state lives: the card is in a graveyard a moment after it resolves, so neither can sit on it. The restriction is one-way player state (`has_city_s_blessing`'s shape) enforced in `_cast_actions`, which is also why lands are unaffected; the copy is a rule rather than an ability, for suspend's ticking reason, and goes through the same `put_copy_on_stack` `copy_spell` uses. "Except for its epic ability" is one condition — `not obj.is_token` — and without it each upkeep's copy re-points `epic_source` at itself, then is removed by a state-based action, silently ending the copying after exactly one turn |
| **Aura swap** | "{cost}: Exchange this Aura with an Aura card in your hand" — one op, because a bounce beside a put-onto-the-battlefield loads and goes wrong twice invisibly. The incoming Aura is not *cast*, so it has no targeting clause to carry a creature and `_attach_aura` never runs; a state-based action then bins it, and the ability reads "exchange" while being a slow Naturalize on your own card. And the exchange would not be atomic — between the two moves the enchanted creature is unenchanted. The attach happens after the move, since `reset_permanent_state` clears `attached_to` on the way in. An empty hand does nothing rather than bouncing the Aura for free |
| **Soulbond** | "Pair this creature with another unpaired creature when either enters… As long as this creature is paired, **both** creatures get +1/+1." `attached_to` is the nearest existing relationship and is wrong twice over: it is one-way, so a one-sided link buffs exactly one of the two; and an Aura attached to nothing is binned by a state-based action, where a creature whose partner died is simply unpaired. Two lifetimes, two fields. `paired_with` is therefore symmetric, and breaking it is two writes — the leaving object's own is cleared by `reset_permanent_state`, the *partner's* in `_detach_all`, since nothing else walks back along the link and a creature pointing at a card in a graveyard would keep the bonus for ever. The static is written once and applies to two creatures, hence `paired` and `paired_with_source`; both are board state, so neither makes one static depend on another's output |

## Simplified

Each of these is a deliberate trade. The rationale matters more than the rule.

| Simplification | What it means | Why |
|---|---|---|
| **No layers system** | Continuous effects apply in a fixed order; static filters and static "as long as" conditions read pipeline *inputs* only — printed characteristics, board state, counters, zone counts — never another static's output, enforced at load time | The full layer system with timestamps and dependency analysis is a large subsystem that would change no outcome for any card in these decks |
| **Automatic mana payment, by default** | The solver picks which land to tap, preferring to spend abundant colours so scarce ones stay open. A land doubled by Vorinclex — or a mana rock doubled by Kinnan, Bonder Prodigy, whose printed sentence is the same one about a *nonland* permanent — adds **one** mana of a type it produced, and does not offer a free choice of which, because a mana ability may never stop to ask; the extra is the first symbol in WUBRGC order the source actually made. It formerly doubled the whole option, which is the same number for every one-mana source and one too many for any source that makes two: a Sol Ring under Kinnan is `{C}{C}{C}`, not `{C}{C}{C}{C}`. Nothing in the pool exercised it until Kinnan arrived, so the error was silent and in the strictly-better direction; pinned now in `tests/cards/test_the_ur_dragon_mana.py`. A seat can opt out with **manual mana** (`PlayerState.manual_mana`, the rail's Auto mana / Manual mana toggle), which offers every tap-only mana ability as an action and one action per colour a dual could make. Off for AI seats, so the RL action space is unchanged. Independently of the toggle, a permanent that offers something *besides* its tap-only mana ability offers both to a human seat (`PlayerState.offer_all_abilities`): a Forest stays the solver's, a Mind Stone shows its sacrifice ability *and* its tap | Removes an enormous branching factor for the RL agent and the worst tedium from the UI, without making "tap this land for blue" impossible to say — or letting one click spend a permanent that had more than one thing to do |
| **"Enchant creature" is a targeting clause, not a standing restriction** | 702.5b makes an Aura's enchant ability a restriction on what it may ever be attached to. The engine reads it as the Aura *spell's* target selector and nowhere else, so an `attach` op that names a host with `attachment` is trusted: the card's own selector is the whole check, and nothing re-tests it if the Aura is later moved onto an illegal permanent | Every Aura the engine can be handed arrives one of two ways — cast, where the target line **is** the restriction and is re-checked on resolution (608.2b), or put onto the battlefield by an effect whose own selector states the host. Modelling it a second time would mean a per-`CardDef` enchant filter that only ever repeated what the target line already said. `attach` still refuses self-attachment (301.5c) and protection, which are the two restrictions that are *not* on the card. The same reading covers **"Enchant player"** (303.4a): the seat is the spell's target, `attach_to_player` checks only that the player is still in the game, and neither of `attach`'s two restrictions has a counterpart — a seat cannot be the permanent attaching to itself, and no card the engine can be handed gives a player protection |
| **Which same-coloured mana gets spent** | The pool records, pip by pip, which permanent made each mana **and what that permanent was** (`Pip.source_traits`, a `ManaOrigin` snapshot), so both "when that mana is spent" and "if mana from a Treasure was spent" are answerable — the second needs the snapshot because a Treasure is sacrificed to make its mana and its oid is dangling by the time anything asks. Which of two identical pips a payment consumes is the player's choice at a table; `ManaPool._take` pops newest-first | Payment taps what it needs immediately before spending, so the newest pip is the one just made for this spell — which is the only case Path of Ancestry or Opal Palace is ever played for. Asking would put a decision inside cost payment, which is where mana abilities are forbidden to stop |
| **A mana source's characteristics are frozen when it makes the mana** | `mana_source_traits` snapshots name, types, subtypes, supertypes and controller at the instant of production, and every later "mana from a …" question is answered off that snapshot rather than off the board | The source is routinely *gone* — every Treasure sacrifices itself to pay — so there is nothing left to re-read, and a reading that waited would answer "no" for the one card the clause is printed on. The reachable divergence is a permanent whose type line changes between making the mana and the mana being spent (a land animated after tapping, a Treasure that stops being one); the snapshot answers as of production, which is what "mana **from** a Treasure" says |
| **A reflexive trigger resolves inside its own ability** | "You may sacrifice a Vampire. **When you do**, Sorin deals 3 damage to any target" is written as a `may` with a sacrifice `pay`, so the payload runs in the same resolution instead of going on the stack as its own object. The option is still withheld when you control no Vampire, and the payload still runs only if the sacrifice completed | Same trade as delayed triggers and mode-before-target above: observable only to somebody who would respond differently to the reflexive half than to the ability that scheduled it. What it costs is the response window between the sacrifice and the damage, and the targets being chosen at activation rather than when the reflexive half would go on the stack — which never gates activation, since a player is always a legal "any target" |
| **Gate 5 cannot witness a loyalty ability** | The authoring harness casts a card and stops at the first priority window; it never activates anything. So a planeswalker's abilities are checked by the vocabulary and text-attribution gates alone, and its starting loyalty is the only thing the behaviour gate can assert | Making ability bodies falsifiable means teaching the harness to activate them, which is a different piece of work. `tests/unit/test_planeswalkers.py` is what holds the chassis; a card's own abilities are held by the same gates every other card's activated abilities are |
| **Automatic damage assignment order** | Blockers are ordered by effective toughness ascending; the attacker is never asked | One more decision point per combat for a choice that is nearly always forced |
| **`search_zones` always searches every zone it names** | Finale of Devastation prints "If you search your library this way, shuffle". The `if` is there because a player at a table may announce they are searching only the graveyard; `search_zones` always offers both zones as one pool, so it has always searched the library and always shuffles | Making it conditional means asking which zones to search *before* showing the pool, which is a second decision on a card that has none, and it would undo the one thing the op exists for — that "and/or" lets you see both before committing. The only reachable difference is a player who would decline the search to keep a stacked top of library, and they give up the union to do it |
| **Automatic trigger ordering** | Simultaneous triggers you control resolve in a fixed order rather than one you choose | Matters only for a handful of interactions, none of them in these decks |
| **Card-level targets chosen before modes** | A modal spell picks its mode as it is cast (rule 601.2b), but a **card-level** target is enumerated as part of the cast *action*, so it is chosen first — the reverse of the printed order. A **mode-owned** target is not: it is declared inside the cast, after its mode (see mode-owned targets under Implemented). A **triggered** ability has no card-level half of this problem at all — 603.3d asks its modes and then its targets as it is put on the stack, in the printed order. Only a **nested** `choose_mode` still resolves late, having no single question to answer early | Only the card-level half is left, and the shared `optional: true` idiom in [card-dsl.md](card-dsl.md) is what papers over it. Closing it entirely means moving *all* target enumeration behind a decision, which changes casting for every card and both AI seats; a mode-owned spec did not need that, because there is nothing to enumerate until the mode is taken |
| **X capped for the policy** | A human is offered every X from 0 up to what the board can pay. The RL policy sees X ∈ 0..9, because `CHOICE_CAP` in `ai/action_space.py` is 10 and `IDX_CHOOSE` sits below `IDX_YES` in the index layout | Raising the cap shifts every index above it and invalidates trained checkpoints, for a ceiling that only bites above ten spare mana |
| **"As this enters, choose…" is a trigger** | Vanquisher's Banner's "as this artifact enters, choose a creature type" is implemented as a `self_enters` trigger, so the type is chosen a moment *after* the permanent arrives rather than as it does. Until it is chosen, the filters it feeds match nothing | `zones._enter_battlefield` applies enter-replacements synchronously and cannot yield a decision. The window is observable only by another trigger ordered between the two, and closing it means making the replacement whitelist generator-driven |
| **Object identity survives zone changes** | The `oid` is preserved where the rules would create a new object; permanent state is reset instead | Simpler and equivalent for everything except effects that track "the new object" |
| **Last-known information is explicit** | A card that needs a value after its target has left declares a `snapshot` op (see Swords to Plowshares). The one place a card cannot reach that way is a **`dies` trigger about itself** — an op runs at resolution, by which time the creature has gone — so `zones.move_object` snapshots the last-known power and toughness beside `had_counters`, read back through `power_had` / `toughness_had` (Goldvein Hydra). Still explicit and still event-scoped: two more keys on one event, not a table of every object's history. The **second** blind spot is a permanent somebody *else* chose inside an op — Entrapment Maneuver's "target player sacrifices an attacking creature of their choice… X is that creature's toughness" — where no op outside `sacrifice` can name the object while it is still on the battlefield, and every route afterwards reads the *printed* value (a 5/5 with three +1/+1 counters reports 5, not 8). `sacrifice` grew a `snapshot` key filled in the window it already writes `as` in; `toughness_had` cannot substitute, being bound only by the dies and leaves-battlefield trigger events | A global LKI system for two cards is not worth it; the explicit form is also easier to read. The decision stands — what changed is that `snapshot` had a blind spot, and `had_counters` was already the precedent for filling it. `counters_had` is the near miss and misses an anthem, a pump spell or a -1/-1 counter: it and `power_had` agree only on the board where neither matters |
| **Commander replacement is automatic** | A commander always returns to the command zone rather than being asked | It is what players choose in practice, and it keeps zone changes out of the decision system |
| **Legend rule keeps the newest** | Duplicated legends are resolved without asking the controller | The choice is nearly always irrelevant |
| **Target options capped at 12** | A spell offers at most 12 target combinations | Only bites on very wide boards; without it a single "target creature" can flood the action space |
| **Turn cap** | 30 turns per player (60 in a duel, 120 in a pod), then a draw | Self-play must terminate. Draws are counted and reported |
| **Trigger loop guard** | More than 200 triggers in one step raises `RulesLoopError`, scored as a draw | One pathological board must not abort a 10,000-game run |
| **Extra phases capped at 20 per turn** | Grants past `MAX_EXTRA_PHASES_PER_TURN` are dropped rather than queued | "Untap all creatures you control; there is an additional combat phase" plus enough mana is a real printed infinite combo (Aggravated Assault), and the rules let it run for ever. Twenty is far past anything a game turns on, and an unbounded turn is a hung process rather than a loss |
| **Delayed triggers resolve off the stack** | "At the beginning of the next upkeep, draw a card" runs as the step begins rather than being put on the stack | Same trade as modes and trigger ordering: only observable when somebody would respond differently to the delayed half than to the spell that scheduled it |

### Simplifications *inside* a hand-written card

Everything above is a deliberate, engine-wide trade. There is a second kind that
was never decided and never written down: individual precon cards that implement
less than they print.

`data/decks/*.deck.json` records `substitutions` — Scute Swarm swapped for
Tireless Provisioner because copy effects did not exist. That mechanism only ever
covered swapping one card for another. It has nothing to say about Tireless
Provisioner itself dropping the Food-or-Treasure choice, Krosan Tusker shipping
as a vanilla 6/5 with no cycling, or Anticipate being implemented as Preordain.

Those cards predate the authoring pipeline and never cleared its gates. The
current count is in `tests/cards/precon_deficits.json`, which is generated, and
the whole picture is `python scripts/audit_cards.py`. They are not new bugs —
they are the cost of building the precons before the gates existed, measured for
the first time. Repair one with `/author-cards <name>`; the mechanics they are
waiting on are `/extend-dsl` jobs, and as of this sequence there are none left
in the report except Kydele's per-turn draw tally. Cycling was
one of them and now ships in full, trigger included, so Krosan Tusker is off
this list. Evolve went with it, on Gyre Sage. Skulk and threshold have both shipped since, and
Nimble Mongoose is off this list. So are intimidate (with the rest of the
evasion family) and investigate — the latter needed no vocabulary at all, only a
Clue in the token pool, and Bygone Bishop is off this list with it.

## Imported cards, which are simplified further

Everything above describes a **hand-written** card. A deck imported from Moxfield
is mostly cards nobody wrote rules for, generated by `src/automtg/cards/proxy.py`,
and those carry a second, much larger set of simplifications. Each is recorded on
the card and shown at import; the full list is in
[deck-import.md](deck-import.md). The ones that change how a game plays:

| Simplification | What it means |
|---|---|
| **Non-keyword rules text is inert** | The card is a real permanent with the right name, cost, types and stats. Its printed abilities do nothing |
| **Front faces only** | A transform or modal DFC generates as its front face. An MDFC land loses the land half |
| **Snow costs are rewritten** | `{S}` becomes `{1}`. Mana value is always preserved. Ordinary hybrid (`{W/U}`, `{2/W}`) and **phyrexian** (`{W/P}`) are now kept exactly as printed |
| **No loyalty; no battles at all** | A proxied planeswalker enters play and then sits there. A **battle is refused outright**: 310.3's printed defense is not a column in the catalog, and a battle entering with no defense counters is defeated by 704.5x as it resolves — so a generated one would vanish rather than be weak. It goes in the import report to be hand-written |
| **One mana per activation** | Scryfall records *which* mana a permanent makes, not how much. A generated Sol Ring taps for one |
| **Some taplands are unconditional** | "Enters tapped unless…" is now read exactly for the three printed shapes that carry the cycle — a basic land subtype test ("a Mountain or a Plains"), a count of other lands, and a count of basic lands — so checklands, slowlands, fastlands and battle lands are the cards in the deck list. The shapes still not read ("unless you have two or more opponents", "unless a player has 13 or less life") enter tapped unconditionally. That fallback direction is fixed on purpose: generating the *upgrade* would hand every imported deck a better mana base than it was built with |
| **`*` power reads as 0** | The characteristic-defining ability behind it is not modelled |
| **Some lands do nothing** | A land whose whole ability the generator cannot express — a bounce land's "return an Island you control" — arrives as an inert permanent. The import report counts those separately from the ones that simply make no mana, because a fetchland makes no mana *by design*. Fetchlands and creature-lands themselves are now [authored](card-authoring.md) rather than generated |

## Not implemented

These are absent, and the curated decks avoid them. Adding any one is additive.

**Card types and mechanics**
Companions. **Planeswalkers and battles are implemented** — each has its own
row above, and battles are implemented **without protectors**: see that row for
what a Siege therefore cannot do here. **Sagas are implemented** — see their own
row above; the three rules the reminder line names live in `engine/sagas.py`, in
`turn` and in `sba`, and no card writes any of them. **Vehicles** and **face-down
creatures** are implemented (crew, morph, manifest). **Transforming** cards are
implemented (above), and so are **split cards, adventure and aftermath** — one
card with a `second_face` that is *cast* rather than turned over to. **Modal
double-faced cards** are the same mechanism with a permanent on the other side
and no rider on where the card goes, so nothing in the engine refuses one; no
shipped card exercises it, so it is untested rather than implemented. **Fuse** ("you may cast one or both halves")
is implemented as a third cast line built from both halves at once.  **Partner** is accepted as an inert
keyword: it is a deck-construction rule, and the engine is handed a finished deck

**Costs and casting**
Alternative costs in general (evoke is implemented) · snow mana ·
convoke and similar · overload

**Phyrexian mana** is implemented (107.4f): `{W/P}` parses as a hybrid pip whose
alternative half is 2 life, and legality offers one cast line per number of pips
bought that way, bounded by 118.4. Every other cost (activations, special
actions, "unless pays") asks how many pips to buy while paying, so a Phyrexian
pip in an **activated ability's** cost is payable with life too. **K'rrik, Son of
Yawgmoth**'s "for each {B} in a cost, you may pay 2 life" is the
`black_mana_as_phyrexian` player-wide static, which reads each `{B}` -- and each
hybrid pip payable with black -- as a `{B/P}` in every cost its controller pays.
**Not modelled**: when two *different* life-payable pips sit in one cost (a
`{2/B}` beside a `{B/R}`, or a `{W/P}` beside a `{B}` under K'rrik), the engine
buys single-symbol pips first and then in printed order rather than asking which;
no shipped card prints such a cost. Under K'rrik the `{B}` in a **strive**
surcharge is paid with mana (no shipped strive card prints `{B}`).

**"You may spend mana as though it were mana of any color"** is implemented in
both of its printed shapes. Granted for one card -- Elder Brain's "...to cast
it" -- it is the `any_color` flag on `exile` / `grant_playable`; said about a
player, it is the `spend_mana_as_any_color` player-wide static (Chromatic
Orrery), which loosens every coloured pip its controller pays, in a spell's cost
and in an activated ability's alike. With an `affects_spells` filter (Oath of
Nissa's "...to cast planeswalker spells") it loosens only the cast of a spell
whose printed face matches, and no activated ability. `{C}` is never loosened (colourless is not
a colour) and colourless mana may be spent as a colour (the Mycosynth Lattice
ruling). **Not modelled**: the waiver is applied to a cast line *before* a
convoke or delve reduction is netted out, so a heavily convoked spell under an
Orrery can have a loosened pip absorbed by the discount; legality and payment
agree on it, and it is the pre-existing behaviour of the granted form. The
narrower "spend mana as though it were mana of any **type**" (Mycosynth Lattice)
is not a static -- `as_any_type` exists as a cost reading and as the
`playable_any_type` permission only.

**"You may cast ... without paying their mana costs"** as a *standing board
permission* is the `free_cast_permission` player-wide static (Dracogenesis;
Omniscience with the filter widened), read by
`player_statics.free_cast_permission` every time `casting._cast_options` builds
an object's cast lines. It prices the cast on `casting.FREE_COST` -- the branch
plot has always used -- so no mana is paid at all, coloured pips included, and
601.2b's X is 0 (107.3b) rather than a reduced cost's X still waiting to be
announced. `spell_cost_reduction` is not a spelling of it at any amount, since
every reduction is clamped to the generic part of a cost. The permission is
**optional**: the free line is offered beside the printed one and which was
taken is recorded on `Action.cast_free`, so a player who cares about mana
actually spent can still pay. **Not modelled**: the filter is
`affects_spells`, which reads a printed face only, so it has no `zone` key --
Omniscience's "from your hand" would be granted from every zone the spell is
already castable from, and a card printing that clause is a gap record rather
than an approximation. And the permission alters no timing: a Dragon sorcery is
still a sorcery.

**"Its owner may cast it for {2} rather than its mana cost"** -- airbend
(Avatar's Wrath) -- is the `airbend` op, and it is the only place a **price**
rides on a casting permission. `ObjectState.playable_alt_cost` holds the flat
cost as a printed mana string; `casting._cast_options` passes it beside
`playable_free`, `_cast_variant` prices the line on it directly under the free
branch, and `Game._cast` charges it off the same field. It **replaces** the
printed cost rather than reducing it, which no reduction could do at any amount
(`costs.cost_reduction` clamps every reduction to the generic part of a cost).
The permission names each card's **owner** (108.3), not the resolving
controller, so a creature you had stolen goes back to the player who brought
it, and it lives on the `"while_exiled"` clock -- ended by
`reset_permanent_state` as the card leaves exile, which is 400.7 anyway.
**Not modelled**: the price is a flat cost with no {X} and no additional cost
of its own, and it rides only the plain cast line -- a kicked or bestowed
airbent card is charged from its printed cost, which no printed card asks
about.

**"Can't cast spells from anywhere other than their hands"** -- Avatar's Wrath
-- is the `cant_cast_spells_from_zones` op, which installs a `structs.CastLock`:
a row in a timed table naming the locked seats, the shut zones, and the seat
whose next turn ends it. The zone filter is what the `cant_cast_spells` static
cannot carry (the loader refuses an `affects` beside it on purpose, so a
narrower printed line cannot load as a strictly stronger lock), and the clock is
what no static on a permanent could hold for a sorcery. `primitives.cast_locked_zones`
is read by `casting._cast_actions`, `suspend.cast_for_free` and
`replacements._offer_cast`; the lock is cleared in the caster's untap step and
swept off an eliminated caster by `sba`, the way every other
``until_your_next_turn`` table is. **Not modelled**: `ops_stack.op_cast_copy` is
deliberately outside it -- a copy created on the stack was never in a zone to be
cast from (707.12) -- and the lock says nothing about *which* spells, only
about where they are.

**Effects**
Copying a permanent as anything but a token, **except** as it enters -- 614.1b is
implemented as the `self_enters_as_copy` replacement (Masterwork of Ingenuity,
Vesuva, Phyrexian Metamorph); what remains unimplemented is a copy applied to a
permanent already on the battlefield by anything but `become_copy` ·
damage *redirection* (prevention is implemented -- see absorb for the
per-permanent form and the player-shield row for "prevent all damage to you this
turn"; what is **not** implemented is absorb-N over a player, "prevent the next 3
damage that would be dealt to any target this turn", which is a pool that drains
at a target that may be a creature instead -- the `prevent_damage` op refuses an
`amount` rather than approximating it) ·
granting a *static* or *activated* ability to
another permanent (triggered ones work) · general replacement effects (the whitelist is
five enters-the-battlefield forms; the three that *ask* -- dredge, madness,
miracle -- are implemented separately in `engine/replacements.py`, and **token
creation** has a narrow hook of its own, `replace_token_creation`, described in
the row above). There is still no rule-616 machinery: no event object, no
"replaced by" chain, and no asking the affected player which of two applicable
replacements to apply first (dredge against a draw doubler is the one pair that
is asked). There are now **eight** named hooks rather than one --
`replace_token_creation`, the life loss, the life gain, the draw, the mill, the
counter placement and the damage below, and `replace_graveyard` -- and they are
still named hooks and not the start of a system. (This sentence said **four** for
several capabilities after it had stopped being true; the count is now derived from
the rows rather than carried forward.) A further entry on the
enters-the-battlefield whitelist, or a replacement of anything other than those
eight, is engine work rather than a new key in a card file.

`replace_graveyard` is the one worth calling out separately, because it is the
first of them to replace a **zone change** rather than a quantity: every other hook
takes a number and returns a bigger number, so each could live at the one function
that owns that number. This one is read in `zones.move_object`, gated on
`to_zone is Zone.GRAVEYARD` **alone** so that the printed "from anywhere" really is
anywhere -- a mill, a discard, a spell leaving the stack, a token, a card put there
from exile, and a permanent dying -- and it is therefore the first hook that had to
be *ordered* against replacements already at that site. It runs **after** the
commander replacement, so a commander dying under Rest in Peace still reaches its
command zone; the other order would exile people's commanders. That ordering is
616.1's choice being settled by the engine rather than asked, which is the same
thing this row already records for the commander case. `affects_player` is required
by the loader and has no default in the reader either, because the default that
suggests itself is `"any"` and `"any"` is what turns Leyline of the Void into Rest
in Peace. Pinned in `tests/unit/test_replace_graveyard.py`

**Combat**
Manual damage division · attacking with
creatures you do not control. (**Attacking planeswalkers is implemented** — 506.2
as a third defender kind, held by `tests/unit/test_planeswalkers.py`; this line
said otherwise and was stale. It is load-bearing for the `cant_attack_you` row
above, whose printed sentence ends "…or planeswalkers you control". **Attacking
battles is implemented too** — the same third defender kind with a different
counter on the other end, held by `tests/unit/test_battles.py`; see the Battles
row above for the protector rule it does not have.)

*Manual damage division* means the **ordinary** case: with no banding involved,
the engine sorts the damage assignment order by effective toughness and asks
nobody. That is a real divergence — the attacking player is entitled to that
order — and it stands.

**Banding is implemented**, and the reason it could be is that the divergence
above is about *who is asked*, not about a missing concept. See its own row.

**Structural**
Multiplayer politics (voting) · sideboards and companions · **the initiative**
and the other designated-player mechanics. The city's blessing, **day/night**
and **the monarch** are implemented — see the monarch's own row above, which is
the field day/night introduced with rule 721.3's two inherent triggered
abilities hung off it. The initiative is the same shape with different rules
(it moves on damage to the *permanent* holding it, and it walks the Undercity),
and no card in the pool prints it, so it is unbuilt rather than blocked

## How this is enforced

None of the above is a promise in prose — it is checked:

- The card loader validates every op name, selector key, value form, keyword, type and
  trigger event against the registries. An unknown one raises `DslError` at load time,
  which fails `pytest`, not a game.
- The "statics may not read statics" constraint is a load-time check on every static
  ability's filter.
- `tests/cards/test_every_card_works.py` plays every shipped card in a rigged sandbox
  and asserts it resolves into the right zone, with per-card outcome expectations from
  `tests/cards/expectations.json`.
- `tests/cards/test_hand_written_cards.py` runs all six authoring gates over every
  hand-written card, and separately checks that each card's `oracle_text` is what the
  catalog says it prints — the check that stops a card from being verified against a
  summary of itself. Cards that do not pass yet are listed, with reasons, in the
  generated `tests/cards/precon_deficits.json`; that list can only shrink.
- `tests/cards/test_auto_cards.py` does the same for every machine-authored card.
- Deck legality, colour identity and singleton rules are tested per deck.

If a card in this repo does not work, one of those tests fails.
